概述

公司尽职调查（due diligence）是金融服务中随处可见的工作流。PE 分析师筛选交易、银行信贷团队评估借款人、合规团队入职新实体、保险承保人评估商业投保人。研究遵循一致的模式：取一家公司，跨多个维度调查它，产出一份结构化情报报告，其中每个声明都有来源追踪。

· · ·

架构：多Agent编排

Agent 编排五个研究轨道，每个由专门的 subagent 处理。

DD 需要这种多步架构，因为早期发现会改变后续需要调查的内容。如果公司概况揭示目标是子公司，财务分析需要覆盖母公司。如果诉讼扫描发现 SEC 调查，风险评估就会改变。Deep Agents 的规划工具让编排器在发现改变研究计划时能够适应。

· · ·

实现要点

定义了两个工具： 1. 包装 Parallel 的 Task API 用于结构化研究，带有 Basis-aware 置信度处理 2. 使用 LangChain 集成的网络搜索工具用于合成期间的快速事实查找

创建研究 subagent，然后创建编排器 agent，运行并流式传输执行进度。

· · ·

为什么可观测性对金融服务至关重要

在金融服务中，监管机构、审计师和风险团队越来越期望公司能重建 AI 辅助输出是如何产生的——特别是当这些输出影响重大商业决策时。

六个月后，内部审计师、合规审查员、模型风险团队、投资委员会或监管机构可能会问一份 AI 辅助的尽调备忘录是如何产生的：哪些来源支撑了每个重要结论？附加了什么置信度？人类在哪里审查或覆盖了输出？agent 的过程是否记录得足够好以便重建？在金融服务中，"agent 给了我一个答案"不是一个可辩护的控制姿态。

Agent 复合了非确定性（LLM 输出、prompt 敏感性、开放网络），花费真金白银进行真实的网络研究，最终产出一份监管机构可能最终审计的备忘录。每个声明都必须映射回带有明确置信度标签的主要来源，而且这种映射必须在运行结束数月后仍可审计。Trace 是在运行后存活下来的工件。

合规和审计今天如何工作

金融服务团队已经有一套证明研究备忘录如何产生的系统：分析师工作底稿、引用列表、来源批准、版本历史和合规审查。当 AI agent 介入时，"分析师"不再只是一个人——它是一个由 LLM 调用、工具调用、检索来源、中间输出和状态转换组成的图。除非这些步骤在运行时被捕获，否则最终备忘录可能存活，但产生它的过程会消失。

Trace 恢复了附着点。 它成为机器侧的工作底稿：一个可检查的记录，记录哪些来源支撑了每个重要结论、附加了什么置信度、调用了哪些工具、人类审查在哪里发生、最终输出如何产生。

· · ·

LangSmith捕获了什么

打开任何运行，首先看到的是编排器的计划：一个四阶段 TODO，在任何 subagent 运行之前布局研究策略。

Phase 1 完成后，编排器扇出每个竞争对手的分析（Phase 2），交叉引用工作底稿查找矛盾（Phase 3），合成最终备忘录（Phase 4）。每个工具调用都被捕获。

超越单个 trace

对于一份 DD 备忘录，trace 是审计追踪。对于一个季度内运行的备忘录组合，你还需要模式发现：哪个 subagent 产出最多低置信度输出、哪些目标迫使最多链式 Parallel 后续调用、哪些来源开始返回更薄的内容。LangSmith 在 trace 基础上构建跨运行分析。对于大规模运行尽调的金融服务团队，这种能力将审计追踪转变为运营纪律。

· · ·

适用对象

此架构适用于任何运行公司结构化研究工作流的团队，包括交易筛选、信贷承保、KYB/KYC 入职、M&A 目标评估和供应商风险评估。
