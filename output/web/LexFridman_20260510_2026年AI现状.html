谁在赢？中美AI竞争格局 [02:00]

Lex 用"DeepSeek 时刻"作为切入点：大约一年前的 2025 年 1 月，中国开源公司 DeepSeek 发布了 R1，以远低于预期的计算成本达到了接近 SOTA 的性能，震惊了所有人。从那以后，AI 竞争在研究和产品两个层面都在疯狂加速。

Sebastian：不会有"赢家通吃"的局面。研究人员频繁跳槽换实验室，没有哪家公司能独占技术。差异化因素是预算和硬件资源，不是想法本身。DeepSeek 赢得了开源社区的心，但"赢"有多个时间尺度——今天、明年、十年后。

Nathan：Anthropic 的 Claude Opus 4.5 在 2025 年底引发了有机的、非营销驱动的狂热，尤其在编程领域。Gemini 3 虽然也很强（Google 的营销攻势很猛），但差异化不够明显——人们不怎么谈论它了。Anthropic 的优势在于文化上最不混乱，且重注押在代码上。即使想法自由流动，人力投入和组织文化才是真正的瓶颈。

中国方面，DeepSeek 引发了一场运动——Z.ai（GLM）、MiniMax、Kimi Moonshot 等公司纷纷发布强大的开源模型。DeepSeek 的"王冠"正在被分享，但不是因为它变差了，而是其他公司在用 DeepSeek 的架构做出更新的模型。

中国公司持续开源的动机：美国企业出于安全考虑不会订阅中国 API，但会使用开源模型。这些公司很清楚这一点——开源是一种通过技术影响力获取市场份额的策略。政府也看到了这种国际影响力的价值，所以会持续激励开源。但训练模型很贵，Nathan 预计最终会有整合，只是不会在 2026 年发生——今年的开源模型构建者会比 2025 年更多，其中很多来自中国。

Sebastian 补充：DeepSeek 并没有变差，只是其他公司在用它的架构（比如 Kimi 用了相同架构）做出更新的模型。这再次印证了不会有明确赢家——最新的模型往往就是最好的模型，大家轮流领先。

Nathan 还指出中国公司的激励结构不同：MiniMax 和 Z.ai 已经提交了 IPO 文件，在积极争取西方市场的关注；而 DeepSeek 背后是对冲基金 High-Flyer Capital，在沟通上很神秘（但技术报告仍然公开）。

模型使用习惯与产品差异化 [09:00]

Sebastian 指出 Opus 4.5 的热度有一层需要注意：Twitter 回音室里的宠儿和实际用户量是两回事。ChatGPT 和 Gemini 面向的是想解决日常问题的广大用户群体，这个群体远比编程圈大得多。

品牌认知和肌肉记忆也很重要——ChatGPT 存在时间最长，人们习惯了用它，会推荐给别人，形成飞轮效应。

Sebastian 提出一个有趣的观点：LLM 的个性化会导致多订阅。ChatGPT 有记忆功能，你可能不想让工作和私人内容混在一起。未来人们可能同时有多个订阅——一个干净的工作用，一个私人用。

三人的使用习惯各不相同：

  • Sebastian：日常快速查询用 ChatGPT 非思考模式（auto mode 已经很好了），深度检查用 Pro 模式——写完东西后丢进去让它彻底检查引用、格式、逻辑，然后去吃饭，回来看结果。
  • Nathan：只用 GPT 5.2 thinking 或 Pro，从不碰非思考模式（"你怎么忍受那个？"）。同时开 5 个 Pro 查询，每个找一篇特定论文或检查一个公式。哲学讨论和代码用 Claude Opus 4.5（始终开 extended thinking）。实时信息用 Grok。Grok 4 Super Heavy 在 hardcore debugging 上特别好。
  • Lex：Gemini 用于快速查询和解释性问题（信任它的知识背景），GPT thinking 用于信息检索，Claude 用于代码和哲学讨论。

Nathan 解释为什么他总是开 extended thinking：推理时间 scaling 是让模型边际变聪明的方式，进步很快，你不知道什么时候会解锁新的用例。

用户对模型的忠诚度是阈值效应——某次惊艳体验让你爱上它，某次愚蠢错误让你离开。就像浏览器一样，你用到它出问题才会换。Sebastian 总结得好：你用它直到它坏掉，然后才去探索其他选项。

关于长上下文：Lex 之前是 Gemini 用户（needle in a haystack 最好），但 GPT 5.2 的发布博客展示了疯狂的长上下文分数——从 30% 跳到 70%，像是发现了某种算法突破。所以现在对 GPT 5.2 的长上下文也更看好了。

为什么没人提中国模型的使用体验？ 三人都承认这是事实。Sebastian 认为这是模型和平台的差距——中国模型以开源权重出名，不是以平台体验出名。Nathan 更直接：美国模型目前就是更好，只要它们更好，我就会付费用。中国模型的服务方式（可能因出口管制）用更少 GPU 做推理，导致更慢、错误率不同。但这种竞争会催生创造力——更低价格、免费服务、差异化产品。

2025 年谁赢了？2026 年谁会赢？

Nathan 的判断：2025 年势头在 Gemini 这边（从 Bard 的低谷爬起来），但很难赌 OpenAI 会输——他们看起来总是很混乱，但总能把东西落地。GPT-5 的 high-line 路由功能（大多数用户不再消耗那么多 GPU）肯定帮他们省了很多钱。

2026 年预测：Gemini 会继续蚕食 ChatGPT 的份额（Google 的规模优势、自研芯片不用付 NVIDIA 的疯狂利润率、数据中心先发优势）。企业和软件侧 Anthropic 会继续成功。如果有新范式出现，最可能来自 OpenAI 的研究部门——deep research、thinking models 这些定义性的东西都是他们先做出来的。

但 2026 年的主题可能是规模优化和摘低垂果实，以及智能与速度之间的权衡——这正是 ChatGPT 5 在幕后试图解决的问题。

编程工具：Cursor vs Claude Code [21:40]

Sebastian 用 VS Code 的 Codex 插件——有聊天界面、能访问仓库，但不会接管整个项目。他自称"控制狂"，想看到过程中发生了什么。

Lex 用 Claude Code 是为了练习"用英语编程"的技能。这是一种根本不同的体验：不是微观管理代码生成过程、看 diff、逐行审查，而是在设计空间层面思考，在宏观层面引导。

Nathan 指出一个有趣的现象：Claude Code 对 Opus 4.5 的利用明显更好。你可以同时打开 Claude Code、Cursor、VS Code，选同一个模型，问同样的问题——Claude Code 的表现好得多。这很 remarkable。

Claude Code 让从零构建东西变得有趣——你不用操心细节，信任它会做出好东西。Nathan 用它做数据分析：他的博客会抓取 Hugging Face 上每个数据集和模型的下载量变化，Claude 直接说"好的，我用这些数据做了分析"，这本来要花他好几天。这种体验的核心是：你有一个中间人，不用再做那些痛苦的底层工作来维护各种 web 项目。

Sebastian 分享了一个搞笑的紧急场景：妻子已经在车里等了，他发现不小心拔掉了 GPU 的电源，需要一个 bash 脚本来串联实验和评估。那一刻他用了最快的非思考模型——10 秒拿到了带 tee 命令的 bash 脚本。Lex 评论说这听起来像《碟中谍》。

开源模型生态爆发 [28:30]

两人不看笔记能列出的开源模型：DeepSeek、Kimi、MiniMax、Z.ai、Mistral、Gemma、GPT-OSS、NVIDIA Nemotron、QWEN、Llama... Nathan 笑着说忘了 Llama——"RIP Llama"。

GPT-OSS 的独特之处：第一个真正以 tool use 为核心训练的开源模型。Sebastian 认为这是范式转变——LLM 最常见的抱怨是幻觉，而解决幻觉最好的方式不是让模型记住一切，而是让它调用工具。数学题用 Python 算，事实问题用搜索引擎查。GPT-OSS 会对 Google 做 tool call，找到 FIFA 官网，确认 1998 年世界杯是法国赢的——而不是靠记忆。

但开源生态还没完全利用好 tool use，部分原因是信任问题——你不想让一个模型在你电脑上有权限执行任意工具、可能清空硬盘。需要容器化。

中国模型的许可证优势：完全无限制的开源许可。Llama 和 Gemma 有附加条件（用户量超过某个阈值要向 Meta 报告财务状况），而中国模型没有任何附加条件——这也是它们受欢迎的原因之一。

为什么 OpenAI 也开源：Sam Altman 在发布会上直说了——"我们 GPU 不够用，开源让你们用自己的 GPU 跑我们的模型，我们还能获得分发"。对 OpenAI 来说零成本。

开源的多重价值：

  • 对用户：可以本地运行，数据不用发到云端
  • 对企业：可以定制、post-training、加入专业数据（法律、医疗等）
  • 对研究：Nathan 提到完全开放的项目越来越多——AI2 的 Olmo（发布数据和代码）、LLM360/K2、瑞士的 Apertus、Hugging Face 的 SmallLM、NVIDIA Nemotron 开始发布数据、Stanford 的 Marin 社区项目。2024 年只有 AI2 一家在做这种完全开放，现在有一大批。

Nathan 还指出一个趋势变化：中国开源模型往往更大（大型 MoE），而美国/欧洲的热门模型（Gemma、Nemotron）往往更小。但这正在改变——Mistral Large 3 是巨型 MoE（类似 DeepSeek 架构），RCAI 和 NVIDIA 都在预告 400B 参数级别的 MoE 模型，预计 2026 Q1 发布。

Transformer架构：变了多少？ [38:00]

Sebastian 的核心观点：从 GPT-2 到今天的前沿模型，架构本质上没变。你可以从 GPT-2 出发，逐步添加改动得到任何现代模型。他在书的附加材料里就是这么做的——从 GPT-2 模型出发，编辑不同组件，就能得到 Olmo 3、Gemma 3 等模型。

主要的架构改动（都是"调参"级别）：

  • MoE（Mixture of Experts）：把 transformer 里昂贵的全连接层扩展为 256 个"专家"网络，但每次只激活少数几个。一个路由器根据输入 token 决定用哪些专家。好处是在不增加每次前向传播计算量的情况下，把更多知识塞进模型。坏处是训练更复杂（可能 collapse），所以 Olmo 3 仍然用 dense 架构。
  • Multi-head Latent Attention（DeepSeek 的创新）：压缩 KV cache，使长上下文推理更经济
  • Group Query Attention：从 multi-head attention 的微调，仍然很流行
  • Sliding Window Attention：Kimi 等模型使用
  • RMS Norm 替代 Layer Norm：只是归一化方式的微调
  • 激活函数：从 sigmoid 到 SwiGLU，类似于当年从 sigmoid 换成 ReLU——不改变网络本质

年底出现的新方向：QWEN3Next 加入了 gated delta net（受 state space model 启发），用固定状态替代部分 attention，使推理成本线性增长而非二次方。还有 text diffusion 模型（完全不同的范式）和 Mamba（state space model），但都有 trade-off——自回归 transformer 仍然是 SOTA，没有被替代。

那进步到底来自哪里？ Sebastian 和 Nathan 的回答：

1. 训练方法的演进：从只有 pre-training（GPT-2 时代）到现在的 pre-training → mid-training → post-training 三阶段流水线。ChatGPT 本质上就是 GPT-3（架构和 GPT-2 一样），新的是加了 SFT 和 RLHF。 2. 系统优化：FP8/FP4 训练让每个 GPU 的 tokens/second 从 10K 提升到 13K。省内存 → 少通信 → 训练更快 → 能跑更多实验 → 找到更好配置。代码库完全不同了，即使架构看起来一样。 3. 数据质量：不再是"把所有东西都扔进去"，而是精心策划——合成数据（把 Wikipedia 改写成 Q&A）、OCR 提取 PDF、数据混合比例优化（用小模型在不同混合上做实验，线性回归找最优比例）。

Scaling Laws：三个维度都还在涨 [48:00]

Nathan 对三种 scaling 都看好：

1. Pre-training scaling：power law 关系在 13 个数量级的计算量上一直成立。"为什么它会停？"从根本上说不太可能停止，只是我们可能无法测试更大的规模了。但成本结构很关键——训练本身可能只要 $2-10M（DeepSeek 报告 $5M，AI2 的 Olmo 3 含工程问题和多次重跑约 $2M），但服务数亿用户是数十亿美元的开销。所以你想让模型更小（降低服务成本），同时通过更好的训练让它更聪明。

2. RL scaling：O1 论文展示了对数增加训练计算、线性提升评估分数。AI2 的实际经验：Olmo 的 RL 从 5 天延长到 3.5 周，模型明显变好了。Grok 4 据说 post-training 计算量已经接近 pre-training。

3. Inference time scaling：让模型生成更多 token 来思考。这是今年最大的体验变化——以前第一个 token 立刻出来，现在模型会思考几秒、几分钟甚至几小时才给你答案。这解锁了 tool use 和软件工程能力：模型在思考过程中尝试工具、看返回结果、再试另一个 API，很快就学会了用 CLI 命令操作仓库、管理 Git。

Pre-training 死了吗？ Nathan 说这是"vibes"而非实践——人们说 pre-training 死了，但实际上所有实验室都还在做。低垂果实确实在 RL 和推理 scaling 那边，但你最终还是想要更好的 base model。Sebastian 补充了一个经济学视角：pre-training 是固定成本（训练一次，能力永久保留），inference scaling 是按查询付费。如果模型半年就被替换，也许不值得花 $100M 训练，不如用推理 scaling 补。

2026 年的大事：Blackwell 集群上线（千兆瓦级数据中心）。这些是 2022-2023 年签的电力和数据中心合同，2-3 年建设期后终于到位。XAI 预计年初达到 1GW、年底 2GW。新算力会同时用于 pre-training 和 RL。Nathan 预测今年会出现 $2000 的订阅层级（从 $200 再 10x）。

RL 训练的系统架构：两组 GPU——actor（生成 completion）和 learner（做梯度更新）。Actor 可以分布在世界各地做不同类型的问题，然后把结果发回紧密互联的 learner 集群。这种异构计算的特性使 RL 比 pre-training 更容易扩展（pre-training 需要所有 GPU 同时在线，100K GPU 的集群几乎保证随时有 GPU 故障）。

Pre-training 数据的演进：

  • 不再是"把所有东西扔进去"，而是精心策划数据混合比例
  • 合成数据不等于"AI 编造的数据"——更多是 OCR 提取 PDF、把文章改写成 Q&A 格式、重新措辞使语法更规范
  • 数据集规模以万亿 token 计：小模型 5-10T，QWEN 文档记录到 50T，闭源实验室传闻到 100T
  • 数据质量 > 数据量：Olmo 3 用更少数据训练出更好的模型，关键是质量
  • 最有价值的贡献往往不是算法突破，而是"找到更好的数据"或"让基础设施快 5%"
  • 训练数据是最严格保密的秘密之一——法律原因，实验室会训练模型不泄露数据来源
  • 有些项目尝试只用明确授权的数据训练（而非 Common Crawl 这种未经许可的全网抓取）

RLVR：2025年最大的post-training突破 [01:37:00]

Nathan 是 RLVR（Reinforcement Learning with Verifiable Rewards）这个术语的命名者之一（来自 AI2 的 Olmo 工作），虽然真正把它 scale 起来的是 DeepSeek。

RLVR 的核心思想：给模型一个问题和正确答案，让它自己摸索解题过程。不约束中间步骤，只验证最终答案是否正确。强化学习的经典框架——agent 在环境中行动，环境返回状态和奖励，目标是最大化奖励。在语言模型的场景下，奖励就是在可验证任务（数学题、代码测试）上的准确率。

适用领域：数学和代码是经典场景。更前沿的方向是 rubrics（评分标准）——用另一个 LLM 定义"好答案长什么样"，然后让模型反复尝试并打分。这把 RLVR 推向了更开放的领域（科学问题、更模糊的任务）。

DeepSeek R1 的"aha moment"：模型自发学会了逐步推理、自我纠错。Sebastian 强调这有多美——你只给问题和答案，模型自己发展出了像数学家一样的分步推导过程，甚至会说"啊，我这里搞错了，让我重来"。这不是教它新知识，而是解锁 pre-training 中已有的知识。

Sebastian 的实验：QWEN 3 base 模型在 Math 500 上从 15% 准确率，仅 50 步 RLVR 就到了 50%。50 步不可能学到新的数学知识——知识已经在 pre-training 里了，RL 只是解锁了它。

Nathan 对此有更复杂的看法：QWEN 的 base 模型有数据污染嫌疑（有论文证明它在 mid-training 阶段训练了几乎和测试集一样的题目）。如果你改变数字但保留文字，QWEN base 会给出高精度小数答案——这说明它在某个阶段用了工具来解题。所以"RLVR 只是格式化"这个说法有一定道理，但不是全部。

Post-training 的完整流程：

1. Mid-training：给模型推理 trace 数据（分步解题过程），让它具备"思考"的基础能力 2. RLVR：让模型在可验证问题上大量试错，投入大量计算做 trial-and-error 学习。随着模型变强，需要不断找更难的问题（简单问题 100% 正确就没有学习信号了） 3. RLHF：最后的润色——调整风格、语气、格式，让模型好用。ChatGPT 之所以神奇就是因为这一步

RLVR vs RLHF 的根本区别：

  • RLHF 没有 scaling law——增加计算不会持续提升性能。经典论文标题就是"Scaling Laws for Reward Model Over-optimization"。偏好是主观的、模糊的，多个正确答案可以共存，最终你只是学到了一个"平均偏好风格"
  • RLVR 有明确的 scaling law——对数增加计算，线性提升性能。O1 论文展示了这一点，DeepSeek 复现了

这意味着 RLVR 的计算预算可以无限增长并持续获益，而 RLHF 更像是"最后的润色"。Grok 4 据说 post-training 计算量已经接近 pre-training——但硬件需求不同：pre-training 是计算密集型（FLOPS），RL 是内存密集型（长序列的 attention 二次方增长）。

下一步（RLVR 2.0）：process reward models 和 value functions——不只看最终答案对不对，还评估中间推理步骤的质量。Process reward models 在 pre-O1 时代被大量尝试过但效果不好，value functions 有更深的 RL 历史根基，人们更乐观但证据还很少。

教育与学习路径 [01:58:00]

Sebastian 的建议：从零实现一个 GPT-2 级别的模型（单 GPU，约 1.2 亿参数），理解 pre-training、attention、fine-tuning 的全流程。目标不是做出能日常使用的模型，而是理解 LLM 里到底进了什么、出了什么、训练怎么工作。

然后看 Hugging Face Transformers 的 config 文件（人类可读的约 100 行），逐步添加现代改动（GQA、RMS Norm、RoPE 等）。关键技巧：加载预训练权重验证正确性——如果你的实现能产生和 Transformers 库一样的输出，就说明你做对了。这就像 RLVR 一样——有可验证的奖励。

Sebastian 分享了实现 Olmo 3 时的经历：RoPE 的 YARN 扩展和自定义 scaling 花了他一天时间才匹配上，但正是在这种挣扎中你真正理解了东西。

为什么不直接从 Hugging Face Transformers 学？ 代码太复杂了——要适配太多用例，有些人用它做生产，代码高度交织、不是线性可读的。它最初是个 fine-tuning 库，后来长成了所有模型架构的标准表示。400+ 个模型实现，可能几十万行代码。但它的价值在于：你有一个 working implementation 可以反向工程。

Nathan 的补充：如果想做研究但没有计算资源，evaluation 是最高杠杆的方向。前沿模型的问题总是被发现得不够快——如果下一代 Claude 的 blog post 里引用了你的 benchmark，你的职业生涯就起飞了。

关于找方向：AI 领域移动太快，最好的人经常因为有更大的低垂果实而放弃当前问题。所以很多窄领域只有 2-3 篇论文，作者可能会回你邮件。Nathan 举例：他对 character training（如何让模型有趣/讽刺/严肃）很感兴趣，一个牛津博士生联系他，他指导了这个学生，论文就出来了。世界上只有 2-3 个人对这个话题真正感兴趣。

关于"struggle"的价值：调查显示资深开发者比初级开发者 ship 更多 AI 生成代码（50%+ 的比例中，资深开发者明显更多）。这可能意味着：专家更知道在哪里用 AI、怎么审查代码、更信任输出。但如果你从不自己挣扎，就永远不会成为能有效使用 LLM 的专家。

Sebastian 的建议：每天留出专门的离线学习时间（比如 2 小时），剩下的时间用 LLM。投资自己仍然重要。

关于编程的乐趣：80% 的开发者觉得用 AI 编程更有趣。但 Sebastian 区分了两种场景——网站维护这种无聊工作交给 AI 很好，但 debug 一个复杂 bug 的成就感是不可替代的。Lex 补充了"pair programming"的价值——不那么孤独了，有个朋友一起穿越沙漠找水喝。

Sebastian 还提出了一个深层担忧：如果你让 AI 做所有你热爱的事，两年后你还会有成就感吗？你还会为自己构建的东西感到骄傲吗？

Text Diffusion：自回归之外的可能 [02:29:00]

Text diffusion 的核心思想：不是一个 token 一个 token 生成，而是并行填充所有 token，通过多轮去噪迭代逐步精化。类似 BERT 的 masked language modeling——你有一个有空缺的句子，一次迭代填充所有空缺，多次迭代逐步改善质量。

Sebastian 解释了为什么这对文本不那么直观：像素是连续的可以微分，但文本是离散的。不过人们找到了实现去噪过程的方法。

优势：速度快（并行生成所有 token）。当 GPT-5 Pro 花 30 分钟响应时，它在一个 token 一个 token 地生成。Diffusion 可以一批生成所有 token。

劣势：推理任务和 tool use 需要顺序执行——你需要调用代码解释器拿到中间结果，这和并行生成冲突。如果要达到同等质量，需要增加去噪步数，最终计算量可能和自回归模型差不多。

Google 宣布了 Gemini Diffusion，声称在大多数 benchmark 上达到同等质量但生成速度快得多（对标 Nano 2 模型）。

实际应用场景：Nathan 听说有 startup 用 text diffusion 做代码 diff 生成——vibe coding 时用户说"做这个改动"，模型需要生成很长的 diff，自回归模型太慢会导致用户流失（每多一秒就丢用户），diffusion 可以快速生成长 diff。

Sebastian 的判断：不会替代自回归 LLM，但会成为快速、廉价任务的选择（比如免费层）。Nathan 补充：他原以为不同类型的模型会更早被用于不同任务，但实际上 tool use 的需求阻止了 diffusion 成为通用方案。

Tool Use与Agent的未来 [02:34:00]

Tool use 是减少幻觉的关键——与其让 LLM 记住"1998年世界杯谁赢了"，不如让它搜索。但 Sebastian 强调这不能完全解决问题：LLM 仍需判断何时调用工具，搜索结果也可能不准确（可能找到错误网站）。

Recursive Language Model 论文的思路：把长上下文任务拆成子任务，递归调用 LLM 解决，最后拼接结果。比把所有内容塞进一个超长上下文效果更好。有趣的是这篇论文只用了 GPT-5 的 API——不需要本地 GPU，学术界也能做。

开源 vs 闭源模型的 tool use 差异：

  • 闭源模型深度集成特定工具（如 Codex 的 GitHub 安全云环境——发送任务、后台执行、返回结果）
  • 开源模型需要兼容多种工具和场景（用户可能用 Exa 搜索，也可能用别的），这更难但可能催生更灵活的架构

Nathan 认为开源模型在 tool use 上暂时落后是必然的（前沿实验室资源太多），但当开源模型解决这个问题时，可能会催生更有趣的创新——比如一个既是 orchestrator 又是 tool use 模型的架构。

Continual Learning与Memory [02:39:00]

Continual learning（持续学习）= 持续更新权重使模型适应新信息。核心问题：太贵了，不可能为每个用户单独更新权重。即使 OpenAI 规模的数据中心也做不到。只有当模型跑在用户设备上（像 Apple 尝试的那样），成本由消费者承担时才可行。

Nathan 更看好 in-context learning：给模型足够好的上下文，它就能表现得像"学会了"一样。问题是之前模型不是为接收大量上下文设计的，agentic 模型才刚开始接受这种用法。

Sebastian 指出实际的"持续学习"已经在发生：GPT-5 → 5.1 → 5.2 就是策划性的快速权重更新——社区反馈什么不行，更新权重，发布新版本。只是不是个性化的。

更激进的例子：Cursor 每 90 分钟根据用户反馈更新模型权重——这是最接近"真实世界 RL"的做法。

Memory 机制：目前主要是 context stuffing（把历史信息塞进上下文）。可以缓存，但仍然消耗 token。LoRA adapter 是另一种选择——只更新一小部分权重（两个小矩阵叠加在原权重上），但"学得多就忘得多"——没有免费午餐。

Context Length的瓶颈与突破 [02:44:00]

从 8K 快速增长到约 100 万 token 后，Nathan 预计 2026 年会到 2-5M，但不会到 100M——那需要真正的突破。

为什么难以继续扩展：

  • 不是计算问题，是内存带宽问题——KV cache 随序列长度增长，attention 的点积运算二次方增长
  • Pre-training 长上下文需要长文档数据，但这种数据很稀少
  • 经验法则：训练上下文长度翻倍需要 2x 计算，然后可以再 2-4x 推理上下文长度

两个方向的解决思路：

1. 架构层面：hybrid attention（transformer + state space model 混合），DeepSeek 3.2 的 sparse attention（轻量级索引器选择需要 attend 的 token，而不是 attend 所有 token）。Sebastian 指出这回到了 attention 的原始理念——选择性关注，而不是"全部关注但有些权重为零"。

2. Agent 自主管理上下文：未来模型会学会何时 compact（压缩历史）。Nathan 描述了一个优雅的问题设定：compaction 作为一个可训练的 action——模型决定何时压缩、如何压缩，目标是用最少 token 保持最高评估分数。现在 Claude Code 用户都怕 compaction（把 10 万 token 的工作压缩成要点列表），但下一代模型会自己控制这个过程。

Sebastian 补充了 Nemotron 3 的例子：找到了 attention 层和压缩状态层的最佳比例——不是全用 attention（太贵）也不是全用压缩（丢信息），而是找到 Goldilocks zone。

AGI时间线与经济影响 [02:59:00]

定义之争：没人真正同意 AGI 和 ASI 的定义。Nathan 倾向于"能替代任何远程工作者"的定义——接收信息、解决数字任务、从反馈中学习。OpenAI 的定义是"能完成一定数量经济价值任务的 AI"。

AI 27 报告的里程碑：超人程序员 → 超人 AI 研究者 → 超级智能 AI 研究者 → 完整 ASI。核心假设是一旦有了超人程序员，其他一切很快跟上。最初预测 2027-28，现在推迟到 2031（均值）。

Nathan 的框架：AI 是"jagged"（参差不齐的）——某些任务超人，某些任务很差。"超人程序员"作为里程碑有问题：模型在前端和传统 ML 上已经很强，但在分布式 ML 训练这种训练数据稀少的领域很弱。他不认为会有一个"完全自动化编程"的时刻，而是人类和 AI 持续共舞——最好的 AI 研究者是那些能弥补模型弱点的人。

Nathan 的预测：软件自动化可能不到 10 年，但 AI 研究自动化要更久。研究是混乱的、社会性的，很大程度上在数据中——AI 模型无法处理这些。

经济影响的真正来源：不是 AGI，而是让全人类知识对全世界可访问。LLM 比 Google 搜索好太多了——你可以问任何问题并得到答案，幻觉越来越少。这意味着理解自己的生活、规划职业、学习人类历史上的任何知识。这不只是美国的事——全世界的孩子都能学到这些。这个安静的力量跨越时间的影响可能比任何单一突破都大——"这就是我们如何到达火星，如何建造这些东西，如何产生一百万个新的 OpenAI"。

Sebastian 补充了一个精妙的区分：对于结构化知识（数学），LLM 最好作为练习生成器和答疑工具，配合教科书使用。但对于稀疏互联网上的个性化信息（比如规划迪士尼行程——你的日期、你的约束、你的预算），LLM 创造了前所未有的价值，因为这种定制化的信息打包以前根本不存在。

关于 tool use 和 computer use：Nathan 认为这是真正的科学问题——"远程工作者"本质上就是 tool use。Computer use（让 AI 操作整个屏幕）2025 年有多个 demo（Claude、OpenAI CUA），但都很差。API 调用比接管屏幕容易得多，这可能是结构性障碍。

开源模型的战略意义：ATOM项目 [03:49:00]

Nathan 发起的 ATOM（American Truly Open Models）项目：

核心论点：开源模型是 AI 研究的引擎——研究者从开源模型起步，因此拥有最好的开源模型 = 拥有 AI 研究的主导权。2025 年 7 月，有 4-5 个 DeepSeek 级别的中国开源模型，美国一个都没有。

  • NVIDIA 的 Nemotron 开始发布数据（对这种规模的公司来说很罕见）
  • Reflection AI 的 20 亿美元融资明确用于构建美国开源模型
  • Jensen Huang 公开谈论这件事的紧迫性

Sebastian 补充了教育角度：如果只有闭源模型，怎么培养下一代研究者？你只能加入公司后才能学习。开源是教育人口和培训下一代的唯一途径。

关于 Meta/Llama 的衰落：Nathan 认为是内部政治斗争和激励错位——研究者想做最好的模型，管理层想要头条新闻，结果过度追求 benchmark 分数（过拟合偏好数据），忽略了社区真正需要的小模型。Llama 4 的负面反馈让公司产生了"我们好心给你开源，你还骂我们"的情绪。

中国开源模型对美国的正面影响：DeepSeek 3.2 发布后没有安全问题，这实际上鼓励了美国公司发布更好的模型——"如果他们能安全发布，我们也可以"。

硬件：NVIDIA能赢多久 [04:00:00]

NVIDIA 的护城河不是芯片本身，而是 CUDA 生态系统——20 年积累的兼容性。Sebastian 回忆 15 年前做分子动力学模拟就用 Tesla GPU。但 LLM 可能加速 CUDA 替代品的开发——"花了 15 年因为很难，但现在有 LLM 了"。

新趋势：训练和推理计算的分离。Vera Rubin 有一款几乎没有 HBM（高带宽内存）的新芯片，专为 pre-fill（大量矩阵乘法）设计，每 FLOP 成本大幅降低。生成阶段（需要 KV cache）才需要内存。

竞争格局：Google 有 TPU，Amazon 有 Trainium，Microsoft 也在做自研芯片。只要 AI 进步速度快，NVIDIA 的灵活平台就有优势。但如果进步停滞，定制芯片就有更多时间追赶。

Jensen 的个人领导力是关键——"还在 Steve Jobs 时代的 Apple"。所有人都说这家公司围绕 Jensen 运转，他对运营的参与度不像其他大公司。只要这种文化持续，NVIDIA 就会继续创新。

关于个人对历史的影响：Nathan 认为 Jensen 让 GPU 革命更快、更聚焦地发生了——没有他可能延迟 10-20 年。同样，没有 Ilya 推动 scaling，GPT 可能不会存在。这些人在正确的时间下了正确的赌注。

100年后的世界 [04:08:00]

100 年后回看，被记住的是什么？

Sebastian：可能是"计算"这个大伞概念——就像工业革命被记住的是"引擎"。不一定是 AI，可能就是"计算机"。

Nathan：deep learning 这个术语可能会被记住，transformer 可能已经被超越。互联网可能被归入"通信网络"的大类。

100 年后的世界长什么样？

Sebastian：专用机器人肯定会有，部分人形。交互设备可能不再是手机或笔记本——也许是脑机接口？但汽车 100 多年了还是方向盘和轮子，所以也许变化没那么大。

Nathan：人们仍然会携带某种私人计算设备——加密消息、加密照片、你的生活。Agency（自主性）和 community（社区）是人类的根本需求，100 年内不会改变。UBI 不能解决 agency 问题。

最后的共识：人类会没事的。AI 是工具——你告诉它做什么，它为你做。意识、agency、社区——这些是人类独有的。在 Terminator 式的场景中，Nathan 认为人类会赢——"我们太聪明了，我们会用本地开源 LLM 来对抗机器"。

未来几年的趋势：物理商品和线下体验的价值会上升，AI slop 会更多更多样，直到社会"淹没在 slop 中然后清醒过来"——物理世界的溢价会越来越高。
