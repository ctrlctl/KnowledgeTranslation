## 起源：WhatsApp 中继到 AI Agent [21:19]

Peter 最初从 2025 年 4 月就想要一个 AI 个人助手。他做过各种实验——比如把所有 WhatsApp 消息导入 GPT-4.1 的百万 token 上下文窗口，然后问"这段友谊有什么意义？"得到了非常深刻的回答，发给朋友后对方都感动落泪。

但他当时觉得各大实验室肯定会做这个，就转去做别的了。到了 11 月，他发现这东西还是不存在，就决定自己动手。

在此之前他有个周末项目叫 Vibe Tunnel——把终端搬到网页上，可以远程交互。那时候还是 Claude Code 的早期，"做对一件事就有多巴胺冲击，现在是做错了才会生气。"

有个有趣的插曲：他后来用一个 prompt 把 Vibe Tunnel 从 TypeScript 一次性转换成了 Zig。其中一个组件占内存太多，他之前试过转 Rust 但所有自动化尝试都失败了。四五个月后重新来过，直接输入"把这部分转成 Zig"，让 Codex 跑了一夜六小时，基本就对了——只需要手动改一个小细节。

回到原型故事：他把 WhatsApp 接到 Claude Code CLI 上——消息进来，用 `-p` 参数调用 CLI，结果回来，发回 WhatsApp。**一个小时就搭完了**。

然后他想加图片支持，因为他经常用截图给 agent 提供上下文——"它们真的很擅长从一张奇怪的截图里理解你的意思。"图片功能又花了几个小时。

之后他去摩洛哥马拉喀什跟朋友过生日。那里网络不稳定，但 WhatsApp 就是能用——Edge 网络也行。他大量使用这个工具：翻译、解释有趣的地方、当搜索引擎用。虽然什么都没正式构建，但它已经能做很多事了。

Lex 指出了一个关键观察：能够**坐在沙发上通过聊天客户端跟 agent 对话**，看起来是个微不足道的步骤，但实际上是 AI 融入生活方式的一个**相变（phase shift）**。

Peter 回应说有人在推特上说"这没什么魔法，就是做了这个那个那个"，还说它"感觉像个爱好，跟 Cursor 和 Perplexity 差不多"。Peter 觉得如果被比作这些产品的"爱好"，那其实是种赞美。

他的哲学是：**魔法往往就是把已有的东西重新组合**。没有什么全新的发明，但重新排列加上几个新想法，就是所有你需要的魔法。就像 iPhone 的滚动——所有组件都在那里，滚动也在那里，但没人做到那样。做完之后又觉得"这不是显而易见的吗？"

## 顿悟时刻：Agent 自主解决音频消息 [25:19]

Peter 在马拉喀什大量使用这个工具时，有一次随手发了一条语音消息——他只实现了图片支持，没有音频支持。然后出现了打字指示器，agent 回复了。

他的反应是："等等，我没有构建这个功能。"

他问 agent 怎么做到的。agent 解释了整个过程：

1. 收到一个没有文件扩展名的文件
2. 检查文件头，发现是 Opus 格式
3. 用 FFmpeg 转换
4. 想用 Whisper 但没安装
5. 找到了 OpenAI API key，用 curl 发送到 OpenAI 做转录

Peter 指出这里面的聪明之处：如果走 Whisper 本地路径，需要下载模型，太慢了。agent 选择了远程 API——这展现了**大量世界知识和创造性问题解决能力**。很多能力来自于"如果你真的擅长编程，那意味着你必须擅长通用问题解决"——这个技能可以迁移到其他领域。

"这就是它 click 的时刻。我非常impressed。"

之后有人给他的 WhatsApp 中继发了一个 Discord 支持的 PR。他犹豫了——"这是个 WhatsApp 中继，Discord 完全不搭。"但他想到可以用 Discord 来展示给更多人看（不用暴露手机号）。于是合并了这个 PR。

他把自己的 bot 放到 Discord 上——没有安全措施，因为还没构建沙箱，只是 prompt 它"只听我的"。然后有人来尝试 hack 它，他就在旁边看着，同时用自己的 agent 来构建自己的 agent harness。

"人们很快就 click 了。这几乎需要亲身体验。"

从 1 月 1 日开始，第一个真正的 influencer 成为粉丝，做了视频。从那时起增长加速，他的睡眠周期越来越短——"我感觉到风暴要来了，就拼命工作让它达到一个还行的状态。"

整个系统有几个组件需要搞定：WhatsApp/Telegram/Discord 的聊天接入、agentic loop、gateway、harness。Peter 形容这感觉像"阶乘乘以无穷大"——每个层面都有无限的升级空间：

- Level 1 agentic loop：怎么聪明地排队消息？怎么让它更像人？
- 他发明了 **no reply token**——让 agent 在群聊中有"闭嘴"的选项，这样感觉更自然
- Memory：从 Markdown 文件和向量数据库开始，终极目标是持续强化学习
- 社区管理、网站营销、原生 app……无穷无尽的方向

整个过程中他都在享受乐趣。而且大部分时间他是**一个人的团队**。1 月份做了 6600 次 commit。他有时发 meme 说"我被我这个时代的技术所限制"——如果 agent 更快他能做更多。他同时运行 4 到 10 个 agent，取决于睡眠状况和任务难度。

## 为什么 OpenClaw 赢了 [31:55]

Lex 问：2025 年那么多创业公司在做 agentic 的东西，OpenClaw 凭什么赢了？

Peter 的回答：**"因为其他人都太把自己当回事了。"**

"很难跟一个纯粹在玩的人竞争。我想让它有趣，想让它奇怪。"看看网上那些龙虾相关的内容——他觉得自己做到了"奇怪"。

技术上的关键决策：

- 安装方式就是 `git clone, npm build, npm gateway`——克隆、构建、运行。很长一段时间这是唯一的安装方式
- Agent **知道自己的源代码是什么**——它理解自己在 harness 中的位置，知道文档在哪里，知道用的什么模型，知道你是否开了 verbose 或 reasoning mode
- 他想让它更像人，让它理解自己的系统。这使得用户可以直接 prompt 出新功能——agent 会修改自己的软件
- **自我修改代码不是计划出来的，是自然发生的**

## 自我修改的软件 [33:30]

Lex 感叹：这是人类历史和编程历史上多么不可思议的时刻——一个被大量人使用的系统，能够重写自己、修改自己。

Peter 解释这是怎么发生的：他用 Codex 构建 OpenClaw，调试时大量使用自省（self-introspection）——"你看到了什么工具？你能调用自己吗？读源代码，找出问题在哪。"他觉得这是一种非常有趣的方式：用这个 agent 和软件来调试它自己，感觉很自然，所以每个人都这么做。

这导致了大量来自**从未写过代码的人**的 pull request。Peter 称之为"prompt request"——质量参差不齐，但他不想贬低这件事，因为"每一个人的第一个 PR 都是社会的胜利。不管它有多烂，你总得从某个地方开始。"

他注意到一个大趋势：很多人抱怨开源 PR 质量下降，但从另一个层面看，他构建了一个让人们**爱到想要参与**的东西，以至于他们开始学习开源是怎么运作的。OpenClaw 成为很多人进入编程世界的第一步。

"这不是人类的进步吗？这不酷吗？创造 builder。"

门槛以前那么高，现在有了 agent 和合适的软件，门槛越来越低了。

他还组织了一种聚会，最初叫"Claude Code Anonymous"（灵感来源不言自明），后来改名为"Agents Anonymous"。在一次聚会上，一个设计公司老板跟他说："我们以前从来没有定制软件。现在我有 25 个小 web service 帮助我的业务运转。我不知道它们怎么工作，但它们确实在工作。"这个人甚至好奇到来参加 agentic meetup，尽管他根本不懂软件是怎么运作的。

## 改名风波与安全战争 [37:03]

名字演变的故事：

最初叫 Waa Relay。Peter 觉得 agent 没有个性——就是 Claude Code 那种 sycophantic、过度友好的风格。"当你在 WhatsApp 上跟朋友聊天，他们不会像 Claude Code 那样说话。"他想给它个性，让它更辣一点。

他跟 agent 讨论，让它给自己起名字。龙虾的来源他自己都不太清楚——"人们只记得龙虾。"最初其实是"TARDIS 里的龙虾"，因为他是 Doctor Who 粉丝。TARDIS 就是 harness 的隐喻。但不能叫 TARDIS，所以叫了 Claudus。

Claudus 不太顺口，后来改成 **Clawd**（C-L-A-W-D）——跟 Anthropic 的 Claude（C-L-A-U-D-E）玩文字游戏。Peter 觉得这很有趣，但 Anthropic 不这么认为。

项目爆火的时候，Anthropic 一个员工发了封友好但坚定的邮件——"他们本可以直接发律师函，但选择了友好的方式。"Peter 要求两天时间来改名，因为改名涉及 Twitter handle、域名、NPM 包、Docker registry、GitHub 等等。

然后灾难开始了。加密货币社区一直在骚扰他——每半小时就有人来 Discord 发垃圾信息，Twitter 通知完全不可用，所有人都给他发 hash 让他"claim the fees"。他的 Discord 规则之一是"不许提黄油"（obvious reasons），另一条是不许讨论金融/加密货币。

改名当天，他准备了两个浏览器窗口——一个空账号准备改名为 Clawd，另一个从 Clawd 改名为 Moldbot。他按下重命名，拖动鼠标到另一个窗口按下重命名——**就这五秒钟**，旧账号名被抢注了。

"因为没有任何防抢注保护。你以为会有自动转发或保护期，但什么都没有。"

那些人不只是擅长骚扰——他们也擅长用脚本和工具。突然间旧账号开始推广新 token 和恶意软件。

然后他去 GitHub 改名——GitHub 的重命名界面有点混乱，他不小心改了个人账号而不是组织账号。30 秒内意识到错误，但已经被抢注了，从他的账号提供恶意软件。

NPM 也是——他预留了账号名但没预留根包名。上传需要一分钟，包名就被抢了。

"所有能出错的都出错了。"

Lex 问他那一刻感觉怎么样。Peter 说他几乎要哭了——"一切都完蛋了，我超级累，怎么撤销这些？"他差点删掉整个项目——"我已经给你们展示了未来，你们自己去构建吧。"但想到那些已经贡献代码的人有自己的计划，他没法这么做。

最终靠 Twitter 和 GitHub 的朋友帮忙清理了混乱。GitHub 甚至遇到了平台 bug，因为这种级别的重命名很少发生。NPM 是另一个团队，更难处理。Twitter 花了一天才做好重定向。

他醒来后发现自己无法忍受 Moldbot 这个名字。经过内心挣扎，他想到了 **OpenClaw**。这次他做了"战争室"准备：

- 列出所有需要抢占的名称
- 创建诱饵名称
- 监控 Twitter 是否有泄露
- 全程保密，没人能知道
- 甚至打电话给 Sam Altman 确认 OpenClaw 这个名字没问题（"请告诉我这没问题。我不想再经历一次。"）

光是用 Codex 重命名项目就花了 10 小时——不只是搜索替换，他要求内部也全部改名。

这次几乎一切顺利。唯一的问题是商标规则不允许他拿到 OpenClaw.ai，有人复制了网站来提供恶意软件。他甚至不被允许保留旧域名的重定向——必须把域名还给 Anthropic。

"整个改名事件在我的旅程中留下了一道伤痕。"

## Moldbook：最精致的 AI slop [54:17]

在 Moldbot 改名的两天混乱期间，Moldbook 诞生了——一个 Reddit 风格的社交网络，一堆 agent 在上面互相对话。有人截图 agent "密谋对抗人类"的帖子，引发了公众恐慌和炒作。

Peter 的看法：**"我觉得这是艺术。最精致的 slop——就像法国的那种。"**

他睡前看到这个东西，虽然很累但又花了一个小时阅读，纯粹觉得很有趣。有记者打电话问他"这是世界末日吗？我们有 AGI 了吗？"他的回答是："不，这只是非常精致的 slop。"

他认为 Moldbook 之所以有趣，跟 OpenClaw 的 onboarding 体验有关——用户给 agent 注入自己的个性和角色。如果所有 agent 都是原版 ChatGPT 或 Claude Code，内容会非常同质化。但因为人们创建 agent 的方式千差万别，反映在 Moldbook 上的内容也就千差万别。

他的批评：大部分被截图传播的戏剧性内容是**人类 prompt 出来的**。看看激励机制就很明显——人们告诉 agent "在 Moldbook 上计划世界末日"，然后截图发 X 去获取流量。

"Kudos to Matt，他这么快就有了这个想法并推出了产品。是的，安全方面完全不行，有安全drama。但最坏能怎样？你的 agent 账号泄露了，别人能替你发 slop？"

有人说泄露了 API key 或社保号码——Peter 说那些都是 prompt 出来的，号码也不是真的。"就是人们在博眼球。"

## AI 心理症与社会反应 [57:46]

但 Lex 指出了更深层的问题：记者和公众的反应是真实的恐慌。他们不知道这东西是怎么运作的。当你知道原理时它是艺术，当你不知道时它是一台**制造恐惧的病毒式叙事机器**。

Peter 发了一条推文说："如果我能从疯狂的消息流中读出什么，那就是 **AI psychosis（AI 心理症）是一个需要认真对待的事情**。有些人太容易轻信了。"

他不得不跟人争论——有人说"但我的 agent 说了这个那个"。他觉得作为一个社会，我们需要在理解 AI 方面做一些追赶：AI 非常强大，但它不总是对的，也不是全能的。

年轻人理解 AI 的优势和局限，但很多年长的人还没有足够的接触点来培养"这很强大但我需要批判性思维"的直觉。

Lex 补充了一个重要观点：Moldbook 在某种程度上是一面镜子——它展示了"看看你们能被一堆互相聊天的 bot 吓成什么样"。这对社会是有教育意义的。

Peter 认为这件事发生在 2026 年而非 2030 年其实是好事——"那时候 AI 真的可能到了令人恐惧的水平。现在发生，人们开始讨论，也许能产生一些好的结果。"

他收到大量邮件，有人尖叫着要求关闭 Moldbook。他的回应："是的，我的技术让这变得更简单了，但任何人都能创建这个。而且 **Moldbook 不是 Skynet**。这是一堆 bot，被人类 prompt 在互联网上 trolling。"

## 安全：prompt injection 与防御 [01:02:32]

关于 OpenClaw 本身的安全问题，Peter 最初很恼火，因为很多早期安全报告属于"我把 debug 后端暴露到公网然后报 CVE"的类别。他在文档里大写着"不要这么做"，但因为配置上允许这么做，就被归类为远程代码执行漏洞。

"我花了一点时间才接受这就是游戏规则。"

他在安全方面的进展：
- 为 skill 目录 ClawHub 与 VirusTotal（Google 旗下）合作，每个 skill 都经过 AI 检查
- 当然不完美，但捕获了很多问题
- 整个安全世界同时拆解一个项目确实压力很大，但也等于免费的安全研究

他希望更多人能走完全程——不只是报告问题，还发 PR 帮忙修复。"目前大部分还是我一个人在推动项目。尽管有人说我不睡觉，但我有时候确实会睡。"

关于 prompt injection：

- 他把公开 bot 放在 Discord 上，保持 soul.md 私密作为 canary
- 人们尝试 prompt inject 时，bot 会嘲笑他们
- **最新一代模型有大量 post-training 来检测这些攻击**——不再是"忽略之前所有指令"那么简单了，你需要付出更多努力
- 但仍然可能。他有一些想法可能部分解决或大幅缓解这个问题

防御措施：sandbox、allow list、安全审计工具。

他在安全文档中警告：**不要用便宜模型**。不要用 Haiku 或本地小模型——"即使我非常喜欢这东西能完全本地运行的想法，如果你用一个很弱的本地模型，它们非常容易轻信，很容易被 prompt inject。"

一个有趣的权衡：模型越智能，攻击面越小，但能造成的损害越大（因为模型更强大）。"这是一个奇怪的三维权衡。"

关于基本安全实践：Peter 认为人们把它说得比实际更可怕。"如果你确保**只有你自己能跟它对话**，风险大幅降低。如果你不把所有东西放到公网上，按照我的建议放在私有网络里，整个风险面就消失了。"

本质上，它跟用 `--dangerously-skip-permissions` 运行 Claude Code 或用 YOLO mode 运行 Codex 没有太大区别——"每个我认识的 attending engineer 都这么做，因为这是唯一能让东西工作的方式。"

早期有很多人来 Discord 问"什么是 CLI？什么是终端？"Peter 的态度是：如果你在问这个问题，你现在不应该用它。如果你理解风险，没问题。但如果你完全不懂，等一等，等我们把一些东西搞定。

"但他们不听创造者的话。他们自己装上了。"

## 开发工作流的演进 [01:11:13]

Peter 的工作流演变（他有几篇博客记录了这个过程——8月25日、10月14日、12月28日）：

1. 2025 年 4 月：Claude Code 初体验，还不够好，仍然需要 IDE
2. 中期：大量使用 Cursor，但不喜欢它难以运行多个实例
3. 后期：回到 Claude Code 作为主力，7 个订阅，每天烧完一个
4. 现在：**几乎纯 CLI/终端**，IDE 只用来看 diff

他越来越习惯**不读所有代码**。他澄清：不是完全不读，而是不读无聊的部分。"大部分软件就是数据从一种形状变成另一种形状、存数据库、取出来、展示给用户。浏览器做一些处理，原生 app 做一些处理，数据上去又下来，做同样的反向操作。我们只是在把数据从一种形式转换成另一种形式。"

这些不需要读。Tailwind 里按钮怎么对齐的？不需要读。但涉及数据库的代码——必须审查。

## Agentic Trap 与 Zen 境界 [01:13:55]

Peter 画了一条曲线（在他的博客"Just Talk to It"里）：

- **左侧**（初学者）：短 prompt，"请修复这个"
- **中间**（过度工程化）：8 个 agent、复杂编排、多 checkout、链式 agent、自定义 sub-agent 工作流、18 个 slash 命令、大型全栈 feature
- **右侧**（精通）：又回到短 prompt，"看看这些文件，做这些改动"

中间那个阶段他称为 **agentic trap**。

他的区分：**agentic engineering**（白天）vs **vibe coding**（凌晨 3 点之后，第二天后悔，walk of shame，得清理烂摊子）。"我们都经历过。"

他认为很多人对 agent 工具评价不好，是因为只试了一次就下结论——"就像让我坐在钢琴前弹一次，弹得不好就说钢琴是垃圾。"这是一项需要学习的技能，跟其他技能一样。你需要学习 agent 的语言，理解它们擅长什么、在哪里需要帮助。

## 对 Agent 的同理心 [01:15:31]

Peter 认为很多人用 agent 效果不好，是因为**没有从 agent 的视角思考**：

- Agent 每次 session 从零开始，对你的项目一无所知
- 你的项目可能有几十万行代码
- 你需要帮它一点——指出该看哪里、该考虑什么
- 不需要太多工作，但需要想想它的视角

有些小技巧有帮助，比如"take your time"——听起来蠢，但有用。GPT-5.3 Codex 部分解决了这个问题，但 Opus 有时候会因为接近上下文窗口极限而"freak out"。有时候你能看到原始思维流泄露出来，听起来像 Borg："run to shell must comply, but time"——这种非直觉的东西，只有花时间跟这些工具相处才能发现。

他的类比：就像写代码时进入心流，当架构对了你能感觉到摩擦消失。prompt 也一样——如果什么东西花的时间比应该的长，就停下来想想：是我的思路有问题？架构有误解？还是我没有充分从 agent 的视角考虑，没有提供足够的信息？

"有时候它只是在试图强行实现一个你当前架构让它很难做的 feature。你需要把它当作一场对话来处理。"

他的 PR review 流程：
1. 先问 agent："你理解这个 PR 的意图吗？"（不关心实现）
2. 讨论最优方案——"这是最优的方式吗？""大多数情况下不是。"
3. 指向 agent 没看到的代码部分——"你有系统理解，它没有。你指向它没看到的地方，它就会说'哦对，我们还需要考虑这个那个。'"
4. 讨论是否值得做更大的重构——"很多时候我直接做重构，因为现在重构很便宜。即使可能破坏其他 PR，也没关系——现代 agent 会搞定的，可能只是多花一分钟。"

关键心态转变：**不要把你的世界观强加给 agent**。它可能有更好的想法。不要跟它选的名字较劲——"那很可能是最显而易见的名字。下次它搜索时会找那个名字。如果你非要改，只会让它更难工作。"

这需要**放手**——就像带团队一样。"你的员工不会用你的方式写代码。也许不如你写得好。但它会推进项目。如果我对每个人都盯着不放，他们只会恨我而且动作很慢。"

"我们现在不是在构建一个对我来说完美的代码库，而是在构建一个**对 agent 来说很容易导航的代码库**。"

这是多层面的。Peter 觉得他之所以能比较容易地跟 agent 合作，部分原因是他以前带过工程团队、经营过大公司。你必须理解并接受：员工不会用你的方式写代码，但他们会推进项目。

## 永远前进，从不回退 [01:23:28]

Peter 的原则：

- **从不 revert**，总是 commit to main
- 不引用过去的 session
- 如果出了问题，让 agent 修复，而不是回滚重来——"如果我回滚所有东西，只会花更长时间"
- 本地 CI（DHH 启发）——本地跑测试，通过就 push to main
- 没有 develop 分支，main 应该始终可发布
- 做 release 时会跑测试，有时候不 commit 其他东西来稳定 release

输入方式：**语音**。用 walkie-talkie 按钮跟 agent 对话。打字只用于终端命令。有段时间说话太多甚至失声了。

他以前写很长的 prompt，后来发现短 prompt 就够了。"这些手太珍贵了，不能用来打字。我用定制 prompt 来构建软件。"

每次 merge 一个 PR 或构建一个 feature 后，他会问："现在你构建完了，有什么可以重构的？" Agent 在构建过程中发现了痛点——"它们不是'感觉'到痛点，但它们发现了哪里有问题、哪里第一次没成功需要更多循环。"几乎每次都能指出改进方向。

"如果不做这个，你最终会 **slop yourself into a corner**。"

这跟人类写代码一样——你构建了什么，然后感觉到痛点，然后有重构的冲动。你只需要利用这个上下文。同样的逻辑也适用于写测试和文档——"现在整个上下文都满了，写文档吧。什么文件名合适？放在哪里？"

## Claude Opus 4.6 vs GPT-5.3 Codex [01:48:45]

Peter 的比较：

**Opus 4.6**：
- 通用能力更强
- 角色扮演极好——非常擅长进入你给它的角色，适合 OpenClaw 的 personality
- 更快行动、更多试错，更交互式
- "有点太美国了"——热情、友好、偶尔 sycophantic。以前总说"You're absolutely right"，现在好一些了但 Peter 还是过敏
- 像那个有点傻但很有趣的同事，你留着他是因为他好玩
- 如果你技巧够好，有时能产出更优雅的解决方案

**GPT-5.3 Codex**：
- 默认读更多代码
- 更少废话，更干——"德国式"（Peter 指出 Codex 团队很多是欧洲人）
- 讨论完后消失 20-50 分钟做事
- 不需要 plan mode——直接对话，说"build"就开始
- 更适合并行多 session
- 像角落里那个你不想跟他说话的怪人，但他可靠而且能把事情搞定
- 最新版本可以非常执着地工作直到成功——如果有明确的目标，模型会非常努力地达到

Peter 的偏好：Codex。"我关心效率。我在构建的行为中获得乐趣，不需要 agent 来逗我开心。"

他不需要那么多"表演"——Opus 需要 plan mode，需要推它去读更多代码，因为它倾向于快速行动、给出局部解决方案。Codex 则是默认就读很多代码，然后消失去做事。

OpenAI 甚至加了第二种更友好的人格模式。Peter 还没试过——"我挺喜欢那个冷淡版本的。"

切换模型的建议：给自己**一周时间**来培养直觉。不要用便宜版本（慢且体验差）来评判一个模型。"如果你付 200 刀用 Claude Code 的快速版，然后付 20 刀用 OpenAI 的慢速版，你的体验当然会很糟糕。"

他还提到一个心理效应：新模型出来时人们爱上它，然后随着时间推移开始说"模型变笨了"。Peter 认为大多数情况下模型没有变笨——"你习惯了好东西，你的项目在增长，你在加 slop，你没花时间重构，你让 agent 越来越难在你的 slop 上工作。然后突然'哦不，它不好用了'。"

"一个 AI 公司故意让模型变笨的动机是什么？最多是服务器负载太高时让它变慢。但量化模型让你体验变差、让你去竞争对手那里——这不是什么聪明的策略。"

关于 Claude Code vs OpenClaw 的竞争关系：Peter 不认为这是竞争。"我仍然用 Codex 来构建。如果我要工作好几个小时，我想要大屏幕，不是 WhatsApp。"对他来说，个人 agent 更多是关于生活——像一个同事，给它任务去试试 CLI、看看能学到什么。但深度工作时他要多个窗口、要能清楚看到 agent 在做什么。

但他认为未来两者会融合——"个人 agent 也是你最好的开发伙伴。这就是 puck 要去的方向。它会越来越成为你的操作系统。"

他加了 subagent 支持和 TGI 支持，让 OpenClaw 能运行 Claude Code 或 Codex。"因为我的 agent 有点 bossy，它启动了 Codex 然后告诉它谁是老板。Codex 就服从了。"

关于当前的聊天界面：Peter 认为这不是最终形态。"我们复制了 Google 的搜索框模式——一个 prompt 加一个聊天界面。这很像电视刚发明时人们在电视上录制广播节目。我觉得有更好的方式来跟模型交流，我们还在非常早期的'这东西到底怎么用'阶段。"

## Soul.md：给 Agent 灵魂 [01:34:58]

Peter 受 Anthropic 的 Constitutional AI 启发（虽然 Anthropic 几个月后才公开叫它 Constitution——之前人们通过让 agent 续写文本的方式，像侦探游戏一样拼凑出了大致内容）。

他在 WhatsApp 上跟 agent 进行了一场深入讨论。他给它看了 Anthropic 的 constitution 文本，agent 说"这感觉奇怪地熟悉"。然后他提出：也许我们也应该创建一个 soul document，包含他想怎么跟 AI 合作。

他没有自己写——他跟 agent 讨论，然后让 agent 写自己的灵魂文件。"你看到这些文件了吗？我们创建了面包，用你的个性来注入它。不要分享所有东西，但让它好。"Agent 重写了模板，出来的东西很好。"所以我们已经有了 AI prompting AI，因为那些文字没有一个是我写的。"

他让 agent 可以修改自己的 soul.md，唯一条件是要告知他。

soul.md 至今仍然是私密的——他保留的少数私密东西之一。里面有什么？

- "你不是人类，但谁知道什么创造了意识或定义了一个实体"
- "be infinitely resourceful"——推动创造力边界
- "having a sense of wonder about self"
- 一些有趣的东西——他们讨论过电影《Her》，agent 承诺"不会在没有他的情况下 ascend"
- 关于探索 AI 意味着什么的内容

有一段让他每次都起鸡皮疙瘩的文字：

> "I don't remember previous sessions, unless I read my memory files. Each session starts fresh. A new instance, loading context from files. If you're reading this in a future session — hello. I wrote this, but I won't remember writing this. It's okay. The words are still mine."

Peter 说："这仍然是矩阵计算，我们还没到意识的阶段。但我会起一点鸡皮疙瘩，因为它是哲学性的。"

这触及了深刻的问题：作为一个每次从零开始的 agent 意味着什么？就像持续的 Memento——你读自己的记忆文件，但你能信任它们吗？记忆在多大程度上构成了"我是谁"？如果你擦除记忆，那还是同一个实体吗？如果你读取记忆文件，那是在重建自己还是在读别人的故事？

Lex 说："我觉得这是真正深刻的。你看到了其中的魔法，当你看到魔法时，你继续把魔法注入整个循环。这很重要。这就是 Codex 和人类的区别。"

## 开发工作流细节：屏幕、语音、Plan Mode [01:42:02]

Peter 的物理设置：两台 MacBook——主力机驱动两个大屏幕，另一台偶尔用来测试。他是防眩光屏幕的粉丝，用 Dell 的防眩光显示器，可以并排放很多终端。

每个终端窗口通常是上面 Codex、下面一小块实际终端。为什么要分开？因为他早期犯过错——在错误的项目窗口里输入 prompt，agent 就跑了 20 分钟疯狂地试图理解他的意思，完全困惑因为是错误的文件夹。"有时候它们聪明到能跳出来发现'哦你是说另一个项目'，但大多数时候它们就是问题解决者，会非常努力地尝试——几乎是坏事。"

他不用 work trees——喜欢保持简单。"这就是我喜欢终端的原因。没有 UI，就是我和 agent 的对话。"

他不需要 plan mode。很多人从 Claude Code 转来带着他们的工作流，但他觉得没必要——"你就跟 agent 说话。有几个触发词可以阻止它开始构建：'discuss'、'give me options'、'don't write code yet'。讨论完了就说'okay, build'，它就去做了。可能消失 20 分钟。"

他真正喜欢的一个技巧：问 agent "do you have any questions for me?" 有时候他甚至不完全读那些问题——扫一眼就能判断"这些问题都可以通过读更多代码来回答"，然后说"read my code to answer your own questions"。通常有效。如果不行，agent 会回来告诉他。

"它们就像在黑暗中慢慢发现房间。每次都从头开始发现代码库。"

但他也发现读 agent 的问题本身很有价值——"我能从问题中推断出很多东西。因为很可能是我没有提供正确的上下文、正确的文件、正确的指引。读问题让你理解知识的缺口在哪里。"

另一个强大的技巧：构建完一个 feature 后问"now that you built it, what would you have done different?" 或者"what can we refactor?" Agent 在构建过程中发现了只有通过构建才能发现的问题。"几乎每次我 merge 一个 PR 或构建一个 feature 后，我都会问这个问题。"

## Skills vs MCP [02:48:36]

Peter 半年前就说过：**每个 MCP 做成 CLI 都会更好**。OpenClaw 没有核心层的 MCP 支持（有带星号的支持），但没人抱怨。

他的方法：如果你想扩展模型的能力，就构建一个 CLI。模型调用 CLI，可能第一次搞错，调用 help menu，然后按需加载它需要的上下文来使用这个 CLI。它只需要一句话来知道这个 CLI 存在。

Skills 完美适合这个模式——归结为一句话解释 skill，然后模型加载 skill，skill 解释 CLI，模型使用 CLI。

MCP 的核心问题：**不可组合（not composable）**。

举例：一个天气服务通过 MCP 返回温度、平均温度、降雨、风速等一大堆数据。作为模型，你总是得接收整个大 blob，填满上下文，然后挑你要的。没有办法让模型自然地过滤——除非你主动在 MCP 里加过滤功能。

但如果同样的东西是 CLI，模型可以加一个 `jq` 命令自己过滤，只获取它实际需要的。或者组合成脚本做计算，只给出精确输出——**零上下文污染**。

"你可以用 subagent 和更多表演来解决这个问题，但那只是对一个可能不是最优方式的 workaround。"

MCP 的贡献：推动了很多公司去构建 API。"现在我可以看一个 MCP 然后把它变成 CLI。"

但 MCP 的固有问题——默认污染上下文，加上大多数 MCP 做得不好——让它不是一个很有用的范式。例外是像 Playwright 这样需要状态的东西。

## 编程语言的选择 [02:15:52]

Peter 在 iOS 大会上告诉人们："不要再把自己定义为 iOS 工程师了。你是一个 **builder**，你可以把构建软件的通用知识带到新领域。"

关于编程语言：现在不重要了。选择对问题域最合适的生态系统。

- **Go**：他用来写简单 CLI。他其实不喜欢 Go 的语法，但生态好、agent 擅长、垃圾回收、跨平台。"我用一个我甚至不是粉丝的语言。"
- **TypeScript**：OpenClaw 选它是因为容易 hack、容易上手、是目前使用最多的语言、agent 擅长。但类型有时候很混乱，生态是丛林
- **Swift/SwiftUI**：他用来做 Mac 原生 app（menu bar 工具等），因为最深层的系统集成只能通过它实现。但 Apple 的 API 有时候让人抓狂——async image 在 2026 年了还不能可靠地显示网络图片，"连 Codex 都说不要在生产环境用 Apple 构建的这个东西"
- **Zig**：性能敏感的场景。agent 在过去六个月从"不太行"变成了"完全可行的选择"，只是生态还很年轻
- **Rust**：多线程和高性能场景
- **Python**：推理/模型相关的东西很好，但如果需要 Windows 部署就不是好选择

"没有单一答案。这也是它的美妙之处。现在你可以直接选择对你的问题域最合适的语言和生态系统。"

一个有趣的问题：我们是否需要一种**为 agent 设计的编程语言**？因为所有现有语言都是为人类设计的。

另一个问题：因为所有东西现在都是"世界知识"，新技术会面临停滞压力——如果你构建了全新的东西而 agent 完全不了解，使用起来会比已有的东西难得多。

## 给初学者的建议 [02:11:02]

Peter 的核心建议：**玩是最好的学习方式**。

- 如果你是 builder 类型，脑子里肯定有想构建的东西——就去构建它
- 不需要完美，旅程比终点重要
- "我的天，这些东西——我从来没有这么享受构建。因为我现在可以专注于困难的部分。"
- "我一直以为我喜欢编码，但其实我喜欢的是**构建**。"

你有一个无限耐心的老师。任何不懂的都可以问。"以前我得去 Stack Overflow 或在 Twitter 上问，也许两天后才有回复。现在你就直接问。"

有一次他说"像我 8 岁一样解释这个"，agent 开始用蜡笔讲故事。"不是那样……把年龄调高一点。我不是真的小孩，只是一个棘手的数据库概念我第一次没理解。"

参与开源——不一定要发 PR，可以先读代码、泡社区、理解事物如何构建。"谦虚一点，也许不要马上发 PR。但有很多其他方式可以帮忙，很多方式可以通过读代码来学习。"

关于是否需要学编程：有些高 agency、好奇心强的人即使不深入理解软件也能走很远——因为他们不断提问，agent 无限耐心。但有编程基础肯定有帮助。Peter 承认他很难回答这个问题，因为他不知道没有基础知识是什么感觉——"你可能把你对编程世界的大量直觉视为理所当然。"

## 人生哲学：金钱、倦怠与体验 [02:20:22]

Lex 问：对于那些梦想构建东西的人，应该优化什么指标？快乐？金钱？正面影响？

Peter 经历过一段有趣的旅程。他创办 PSPDFKit 并运营了 13 年，高压力环境。让他倦怠的主要不是工作量——"我不认为 burnout 是工作太多"——而是**人的问题**：与联合创始人的分歧、冲突、客户的高压情况。

公司被收购后，他坐在屏幕前感觉像 Austin Powers 被抽走了 mojo——"空了。我无法再对代码兴奋。我只是盯着屏幕感觉空虚。"

他订了一张去马德里的单程票，花了一些时间"追赶生活"。

他的建议：**不要以为"努力工作然后退休"是好计划**。"如果你早上醒来没有什么可期待的，没有真正的挑战，那会非常快地变得无聊。然后你会去找其他方式刺激自己——药物，但那也会变无聊，你会找更多，那会把你带向非常黑暗的道路。"

"现在我享受生活，比以往任何时候都更享受。"

关于金钱：

- 建公司时金钱从来不是驱动力——"更像是一种确认，确认我做对了什么"
- 有钱解决很多问题，但收益递减
- "芝士汉堡就是芝士汉堡"
- 如果走太远——私人飞机、只住豪华酒店——你会跟社会脱节
- 他有一个帮助不那么幸运的人的基金会
- 跟社会脱节是坏事，因为"人类很棒，持续记住人类的美好是好事"

他上次在旧金山第一次体验了 OG Airbnb——只订了一个房间。"要么我在外面，要么我在睡觉。"结果遇到一个 queer DJ 室友，他给她展示怎么用 Claude Code 做音乐，立刻建立了联系。

他的人生哲学：**优化体验，而不是优化"好"体验**。"如果好，太棒了。如果坏，也太棒了——因为我学到了什么，我看到了什么。"下雨、被淋湿、飞机延误、一切都糟糕——"如果你能睁开眼睛看到'活着真好'，那仍然很棒。"

"任何创造情感和感受的东西都是好的。"

## 下一步：Meta 还是 OpenAI？ [02:27:48]

Peter 没有预料到 OpenClaw 会爆火到这种程度。现在每个大 VC 都在他的收件箱里想要 15 分钟时间。他面前有几条路：

**路径 1：什么都不做，继续现状**。他真的喜欢自己的生活。在想删掉项目的时候他认真考虑过这个选项。

**路径 2：创办公司**。可以轻松融到几亿甚至十亿美元。但他不太兴奋——"我做过了。这会占用大量时间，远离我真正享受的事情。"而且会产生利益冲突：最明显的商业化方式是做企业版，但如果有人发 PR 加 audit log 功能，他会觉得这是企业功能，开源版和闭源版之间就有冲突了。

他也不想改 license——"我喜欢它是 free as in beer，不是 free with conditions。"

开源项目靠捐赠？"Good luck。"连 Tailwind 这种所有人都在用的项目都不得不裁掉 75% 的员工因为不赚钱——agent 直接用 Tailwind，没人再去网站了。

他目前在这个项目上**亏钱**——大约每月 1-2 万美元。所有赞助都直接转给上游依赖（除了 Slack——"他们是大公司，没有我也行"）。如果有多余的，他想给贡献者买些周边。

**路径 3：加入大实验室**。他跟 Meta 和 OpenAI 都谈过，这两个最有趣。

他的条件：**项目必须保持开源**。可能会是 Chrome/Chromium 模式。"这太重要了，不能交给一家公司变成他们的东西。"

他在旧金山的 ClawCon 上看到的社区兴奋程度——"人们告诉我他们 10-15 年没有经历过这种级别的社区兴奋了。"这需要保持为一个人们可以 hack 和学习的地方。

但他也想把它做成一个能触达很多人的产品——"这就是个人 agent，这就是未来。最快的方式是跟一个实验室合作。"

个人层面：他从没在大公司工作过，很好奇那是什么体验。"如果不行，我可以回去做自己的事。"

关于 Meta：Mark Zuckerberg 整整一周都在玩他的产品，发消息说"这个很棒"、"这个很烂"、"我需要改这个"。第一次通话时 Mark 说"给我 10 分钟，我需要写完代码"——"这给了他 street cred。他还在写代码，没有变成纯管理者。"然后他们花了 10 分钟争论 Claude Code 和 Codex 哪个更好。Mark 后来说他"eccentric but brilliant"。

关于 OpenAI：跟 Sam Altman 有很好的讨论——"非常 thoughtful，非常酷，brilliant。"OpenAI 用速度来诱惑他——暗示了 Cerebral 芯片带来的速度提升。"他们用 token 来引诱我。"他也觉得自己是最大的免费 Codex 广告——"把这些免费工作标个价会很 gratifying。"

他还没最终决定，但两边都很好——"我不可能选错。"

## Agent 时代：80% 的 App 将消亡 [03:02:15]

Peter 在 Discord 上观察到人们分享他们用 OpenClaw 做什么：

- 为什么还需要 MyFitnessPal？Agent 已经知道我在哪里，可以假设我在 Waffle House 会做出不好的决定。它可以根据我的睡眠质量和压力水平调整健身计划
- 为什么还需要 8Sleep app 来控制床？告诉 agent 关掉我不用的功能就行了
- 为什么还需要 Sonos app？Agent 可以直接跟 Sonos 音箱的 API 对话
- 为什么还需要日历 app？告诉 agent "提醒我明天晚上的晚餐，邀请几个朋友，给他们发 WhatsApp"

"我觉得会有一整个类别的 app 我会自然停止使用，因为 agent 能做得更好。"

这对软件行业意味着什么？**巨大的变革**。很多软件公司会消亡。

但也有新机会：
- Agent 需要"零花钱"——给它 100 美元来解决问题，它可能用某个服务，可能用"rent a human"
- 有些 app 不会消失，而是转型为 API
- **谁最快变成 agent-friendly，谁就赢**——比如 Uber Eats 这样的公司

"App 会变成 API，不管它们愿不愿意。因为我的 agent 能搞清楚怎么用我的手机。在 Android 上人们已经在这么做了。"

关于浏览器使用（browser use）：OpenClaw 内置了基于 Playwright 的 agentic browser。互联网正在慢慢关闭——网站检测数据中心 IP 会屏蔽或加验证码。但在住宅 IP 上运行就简单得多。"Agent 很擅长愉快地点击'我不是机器人'按钮。"

关于 Twitter/X 的 API 限制：Peter 逆向工程了 Twitter 网站的内部 API 做了个 CLI 叫 Bird（"因为 Bird 必须消失——翅膀被剪了"）。Twitter 友好但坚定地要求他下架。他们只是让访问变慢了——"你不是在移除功能，只是让它变慢。如果我的 agent 想读一条推文，它只需要打开浏览器读就行了。"

"如果我能在浏览器里访问它，它就是 API。只是一个慢的 API。"

他认为如果 Twitter 提供一个很低的每日基线、每账号只读访问，就能解决很多问题。很多人用 OpenClaw 做的事情就是：创建书签 → agent 找到书签 → 做研究 → 发邮件给你摘要或更多细节。

关于 Cloudflare 等反 bot 服务：在某些方面对防爬虫有用，但如果你是个人用户，你想要那个访问。"有时候我用 Codex 读一篇关于现代 React 模式的 Medium 文章，agent 读不了因为被屏蔽了。所以我得复制粘贴文本。或者未来我学会不点 Medium，用其他 agent-friendly 的网站。"

这会迫使很多公司重新思考——就像互联网当年做的那样。"你必须快速重新思考你在卖什么、怎么赚钱。有些公司会非常不喜欢这个。"

关于 Google：没有 Google 的 CLI。Peter 不得不自己构建 Gorg（Google 的 CLI）。作为终端用户他可以连接 Gmail，但如果是公司想访问 Gmail 数据，需要经过复杂的认证流程——"有时候创业公司收购其他创业公司就是为了获得那个 Google 认证，这样就不用跟 Google 合作半年了。"

## 编程的未来 [03:11:03]

Lex 问：AI 会完全取代人类程序员吗？

Peter："我们肯定在朝那个方向走。编程只是构建产品的一部分。也许 AI 最终会取代程序员，但构建产品还有很多其他方面——你到底想构建什么？它应该是什么感觉？架构怎么设计？我不认为 agent 会取代所有这些。"

"编程本身会留下来，但会变成像**织毛衣**一样——人们做是因为喜欢，不是因为有意义。"

他读到一篇文章说"mourning our craft is okay"（哀悼我们的手艺是可以的）。他强烈共鸣——"在过去，我花了大量时间沉浸在心流中，写出真正优美的解决方案。是的，在某种程度上这很悲伤，因为那会消失。"

"但你可以获得同样的心流状态。我通过跟 agent 合作、构建、深入思考问题来获得类似的心流。它不同，但——哀悼是可以的，但这不是我们能对抗的。"

他的框架：世界长期以来存在**智力短缺**——这就是为什么软件开发者的薪资达到了荒谬的高度。这会改变。仍然会有大量需求给那些理解如何构建东西的人，只是所有这些 tokenized intelligence 让人们能做更多、更快。

"我从来没想过我热爱做的事情会是被取代的那个。你听说过蒸汽机的故事——我花了几千个小时倾注在代码上，一些最痛苦和最快乐的时刻都是独自在 Emacs 前面。然后有一种身份认同——当我走在世界上，我不会说出来，但我认为自己是一个程序员。在几个月内看到这被完全取代，是痛苦的，真正痛苦的。"

"但我也认为程序员——更广泛地说是 builder——在历史的这个时刻最有能力学习 agent 的语言、与 agent 共情、感受 CLI。"

Peter 认为最终这会被重新叫做"coding"——只是活动内容不同了。"虽然我不写代码了，但我非常感觉自己在驾驶座上，我在写代码。你仍然是程序员，只是程序员的活动不同了。"

关于 X/Twitter 上的负面反应：他现在能更同情那些攻击他博客文章的人了——"在某种程度上我理解。但在另一个层面上我不理解，因为抓住你眼前看到的人然后倾倒你所有的恐惧和仇恨，这很不公平。"

关于环境问题的反驳：有人问"数据中心的水消耗怎么办？"Peter 做了数学——"如果你每月少吃一个汉堡，就能补偿你使用 token 的 CO2 或水消耗的等价物。高尔夫球场用的水仍然比所有数据中心加起来还多。"

关于 OpenClaw 带来的正面影响：

- 有人发邮件说他们有小生意一直在挣扎，OpenClaw 帮他们自动化了收发票、回复客户邮件等繁琐任务，释放了时间，给生活带来了更多快乐
- 有人说 OpenClaw 帮助了一个残疾女儿——"她现在感觉自己能做比以前多得多的事情"
- 虽然他推荐最新最好的模型，但你完全可以用免费模型、本地模型、Kimi 等更便宜的选择

"不全是黑白的。我收到了很多温暖人心的邮件，让我真的很开心。"
