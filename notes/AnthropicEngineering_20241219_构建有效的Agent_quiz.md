# 构建有效的Agent — 复习题

## Q1: Agent适用场景的四个共性条件是什么？ (attempts: 2)

**答案：**
1. 对话+行动结合
2. 明确的成功标准
3. 反馈循环
4. 人工监督能有效介入

---

## Q2: Agent设计三原则是什么？ (attempts: 1)

**答案：**
1. 简单性
2. 透明度（显式展示规划步骤）
3. 精心打造 ACI（工具文档+测试）

---

## Q3: Agentic系统的核心trade-off是什么？三级复杂度选择是什么？ (attempts: 2)

**答案：**
用延迟和成本换取更好的**任务表现**（task performance）。

三级：单次 LLM 调用 → 工作流 → Agent

---

## Q4: 文章对框架（如LangChain）的态度是什么？核心问题出在哪？ (attempts: 2)

**答案：**
两个问题：
1. 多了抽象层隐藏 prompt 和 response，丧失可调试性
2. 诱导在简单方案够用时添加不必要复杂度

建议：从直接使用 LLM API 开始。

---

## Q5: Agent的本质架构是什么？ (attempts: 2)

**答案：**
LLM 在循环中基于环境反馈使用工具（while loop + tool call + environment feedback）。

难点不在架构本身，在工具设计和错误处理。

---

## Q6: ACI设计方法论：工具格式三条建议 + 具体做法四条？ (attempts: 2)

**格式建议：**
1. 给模型足够 token 思考，避免写进死角
2. 保持格式接近模型在互联网文本中自然见到的形式
3. 确保没有格式"开销"（不要求精确计数行数、不要求字符串转义）

**具体做法：**
1. 站在模型角度想（仅凭描述和参数使用是否显而易见，含示例、边界、格式要求、与其他工具边界）
2. 参数名和描述改得更直白
3. 测试模型怎么用工具，跑大量示例看犯错，迭代
4. 防呆设计（Poka-yoke，修改参数使犯错更难）

## Q7: 判断该用Agent还是Workflow的核心一句话？四个适用信号和四个反面信号？ (attempts: 3)

**核心判断：**
能提前画出流程图 → 工作流，不能 → Agent

**四个适用信号：**
1. 步骤数不确定（修 bug 可能改 1 个文件也可能改 10 个）
2. 需要从环境反馈决定下一步（跑测试→读报错→改另一个文件）
3. 同一任务的不同实例走完全不同路径
4. 需要错误恢复能力（工具失败后自己换方式重试）

**四个反面信号：**
1. 每次走一样的步骤 → 工作流
2. 不需要工具调用 → 单次 LLM 调用
3. 对延迟敏感 → agent 多轮循环太慢
4. 错误代价极高且不可逆 → 人工审批流更安全

---

## Q8: 面试三步决策框架第三步"加安全边界"的三个维度及具体内容？ (attempts: 4)

**三个维度：**

1. **停止条件**：最大迭代次数、无进展检测、超时、检查点暂停
2. **Guardrails**：
   - 输入侧：injection 检测
   - 输出侧：独立 LLM 审查合规性
   - 执行侧：确认 token / 阈值 / 沙箱
3. **人工介入**：置信度低、不可逆操作、超出预设范围时升级

---

## Q9: ACI防呆设计的三个具体例子？ (attempts: 2)

**答案：**
1. **绝对路径**：参数名改为 absolute_path，完全避免模型用相对路径出错
2. **确认 token**：加入确认入参（如用户对话中说出的原文），没有人工确认信息就无法调用该工具
3. **文件编辑格式 trade-off**：
   - Diff：header 要求预测行数（预知未来）→ 高出错率
   - 重写整个文件：token 多但不易出错
   - Search-and-replace：折中，只需旧文本+新文本
