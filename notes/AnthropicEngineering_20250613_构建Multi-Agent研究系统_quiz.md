# 构建Multi-Agent研究系统 — 复习题

> 来源：AnthropicEngineering_20250613_构建Multi-Agent研究系统

## Q1: Multi-Agent架构相比单Agent的两个核心价值？ (attempts: 3)

**答案：**
1. 并行压缩：sub-agent 在各自 context window 中并行探索，为主 agent 浓缩信息
2. 关注点分离：不同工具、prompt、探索轨迹，减少路径依赖（一个 agent 的发现不影响另一个的探索方向），保证调查彻底性

---

## Q2: Orchestrator-Worker模式中，委派给sub-agent的四个要素？ (attempts: 2)

**答案：**
1. 目标
2. 输出格式
3. 工具和来源指导
4. 清晰的任务边界

---

## Q3: 让Agent改进自身的具体做法？ (attempts: 2)

**答案：**
用 LLM 优化 LLM 的工作环境：
1. 把 prompt 和失败模式给 LLM，让它诊断并建议改进
2. 创建工具测试 agent，让它尝试使用有缺陷的工具然后重写工具描述

---

## Q4: 搜索策略是什么？为什么？ (attempts: 1)

**答案：**
先广后窄：从短而广的查询开始再深入细节。Agent 默认倾向于用过长、过具体的查询，丧失检索广度。

---

## Q5: 评估Multi-Agent系统的三层方法？ (attempts: 3)

**答案：**
1. 小样本快速开始（~20 个查询发现大变化）
2. LLM-as-judge 按 rubric 评分（事实准确性、引用准确性、完整性、来源质量、工具效率）
3. 人工评估补充盲区（如来源质量）

---

## Q6: 工具失败时的恢复策略？为什么不能重启？ (attempts: 1)

**答案：**
让 agent 知道工具正在失败并让它适应。不能重启：重启昂贵（大量 token 和时间重来）且令用户沮丧。

---

## Q7: 什么是Rainbow Deployments？为什么agent系统需要？ (attempts: 2)

**答案：**
逐步将流量从旧版本转移到新版本，新旧同时运行。因为 agent 高度有状态（prompt、工具、执行逻辑），部署时 agent 可能在任何位置，直接切换会丢失状态。旧版本跑完当前任务，新流量走新版本。

---

## Q8: 附录三个实用技巧？ (attempts: 2)

**答案：**
1. 终态评估：评估最终状态而非逐轮过程
2. 长对话管理：总结已完成阶段存入外部记忆，接近 context 限制时生成新 sub-agent 交接
3. Sub-agent 输出到文件系统：写入持久存储传轻量引用，避免"传话游戏"信息丢失，减少 token 开销
