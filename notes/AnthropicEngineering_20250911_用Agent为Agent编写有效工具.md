# 用Agent为Agent编写有效工具

> 来源：output/markdown/AnthropicEngineering_20250911_用Agent为Agent编写有效工具.md

## 要点摘录

### Ergonomic 的含义

**原文：**
> 对 agent 最"人体工学"（ergonomic）的工具，对人类来说也出奇地直观。

**理解/讨论：**
Ergonomic 在工具设计语境中指"用起来顺手、不费力、不容易出错"。好的工具设计是通用的——不管用户是人还是 LLM，命名清晰、参数直观、返回有意义的信息，都是好用的标志。

---

### 工具的本质：确定性与非确定性的契约

**原文：**
> 工具是确定性系统与非确定性 agent 之间的新型契约。Agent 偶尔会幻觉或无法理解如何使用工具。这意味着需要从根本上重新思考为 agent 编写软件的方式：不是像为其他开发者写函数和 API 那样写工具，而是为 agent 设计。

**理解/讨论：**
传统软件是确定性系统之间的契约（函数调用每次行为一致）。工具则面对非确定性的 agent——同一个请求，agent 可能调用工具、从知识回答、或先问澄清问题。核心转变：不能像给开发者写 API 那样写工具，要考虑 agent 的非确定性、可能的误用、需要从描述中理解用法。

---

### 编写工具的三步流程：原型→评估→协作优化

**原文要点：**

**1. 构建原型：**
- 用 Claude Code 快速搭建（可能 one-shot 完成）
- 给 Claude 提供依赖库/API/SDK 的文档（可用 llms.txt）
- 包装为本地 MCP server 或 DXT，连接到 Claude Code/Desktop 测试
- 自己先测，收集用户反馈建立使用直觉

**2. 运行评估：**
- 生成基于真实使用的评估任务（强任务需要多步推理、多次工具调用）
- 用直接 LLM API 程序化运行，简单 agentic 循环（while loop 包裹交替的 LLM 和工具调用）
- System prompt 中让 agent 输出推理块（在工具调用前）→ 触发 CoT 提升表现
- 或开启 Claude 的 interleaved thinking（原生功能，开箱即用）
- 追踪指标：准确率、运行时间、工具调用次数、token 消耗、工具报错
- 追踪工具调用模式 → 揭示常见工作流 → 发现工具合并机会

**3. 与 Agent 协作优化：**
- 将评估 transcript 拼接后给 Claude Code 分析
- Claude 擅长分析 transcript 并一次重构大量工具
- 用 held-out 测试集确保不过拟合

**理解/讨论：**
三步形成闭环：原型→评估发现问题→用 LLM 自动优化→再评估。评估不只看准确率，效率指标同样重要。推理块有双重作用：提升 agent 表现 + 帮开发者定位工具描述的改进方向。

---

### CoT（Chain-of-Thought）

**概念：**
CoT = 链式思考。让 LLM 在给出最终答案之前先输出推理步骤。

**为什么有效：** 模型"边想边说"时，中间推理步骤会影响后续 token 生成，相当于给模型提供了工作记忆，显著提升复杂推理任务的准确率。

**在工具评估中的应用：** 让 agent 在调用工具前先输出推理块，触发 CoT 行为，提升工具选择和使用的准确性。Claude 的 interleaved thinking 是原生实现，不需要手动改 prompt。

---

### Interleaved Thinking

**概念：**
Claude 在工具调用之间自动插入思考步骤的原生功能。开启后能看到模型在每次工具调用前后的内部推理。

**用途：** 探查 agent 为什么调用/不调用某个工具，定位工具描述中需要改进的具体地方。等效于手动要求输出推理块，但开箱即用。
