# 用 MCP 实现代码执行：构建更高效的 Agent

Model Context Protocol（MCP）是连接 AI agent 到外部系统的开放标准。传统上，将 agent 连接到工具和数据需要为每个配对做定制集成，造成碎片化和重复劳动，使真正互联的系统难以扩展。MCP 提供了通用协议——开发者在 agent 中实现一次 MCP，就能解锁整个集成生态。

自 2024 年 11 月推出 MCP 以来，采用速度很快：社区已构建数千个 MCP 服务器，所有主要编程语言都有 SDK，行业已将 MCP 作为连接 agent 到工具和数据的事实标准。今天开发者常规构建可访问数十个 MCP 服务器上数百或数千个工具的 agent。

然而，随着连接工具数量增长，预先加载所有工具定义并通过上下文窗口传递中间结果会拖慢 agent 并增加成本。在这篇博客中，我们将探索**代码执行如何让 agent 更高效地与 MCP 服务器交互**——处理更多工具同时使用更少 token。

---

## 问题：工具定义和中间结果的 Token 膨胀

随着 MCP 使用规模扩大，有两个常见模式会增加 agent 成本和延迟：

### 工具定义过载上下文窗口

大多数 MCP 客户端预先将所有工具定义直接加载到上下文中。在 agent 连接到数千个工具的情况下，它们需要在读取请求之前处理数十万 token。

### 中间工具结果消耗额外 Token

大多数 MCP 客户端允许模型直接调用 MCP 工具。每个中间结果都必须通过模型。例如，将会议记录从 Google Drive 下载并附加到 Salesforce lead 时，完整的通话记录会流经两次。对于 2 小时的销售会议，这可能意味着额外处理 50,000 token。更大的文档可能超过上下文窗口限制，破坏工作流。

## 解决方案：将 MCP 服务器呈现为代码 API

随着代码执行环境对 agent 变得更常见，一个解决方案是将 MCP 服务器呈现为代码 API 而非直接工具调用。Agent 然后可以编写代码与 MCP 服务器交互。这种方法解决了两个挑战：agent 可以只加载需要的工具，并在执行环境中处理数据后再将结果传回模型。

一种方法是从连接的 MCP 服务器生成所有可用工具的文件树。Agent 通过探索文件系统发现工具：列出 `./servers/` 目录找到可用服务器，然后读取需要的特定工具文件来理解每个工具的接口。这让 agent 只加载当前任务需要的定义。

**这将 token 使用从 150,000 token 减少到 2,000 token——节省 98.7% 的时间和成本。**

![](images/fig_02.png)

Cloudflare 发布了类似发现，将 MCP 的代码执行称为"Code Mode"。核心洞察相同：LLM 擅长编写代码，开发者应该利用这一优势来构建更高效地与 MCP 服务器交互的 agent。

## 代码执行的优势

代码执行与 MCP 使 agent 能更高效地使用上下文——按需加载工具、在数据到达模型前过滤、在单步中执行复杂逻辑。使用这种方法还有安全和状态管理方面的好处。

### 按需工具发现

模型擅长导航文件系统。将工具呈现为文件系统上的代码允许模型按需读取工具定义，而不是预先全部读取。或者，可以添加 `search_tools` 工具来查找相关定义。

### 数据过滤与转换

处理大型数据集时，agent 可以在代码中过滤和转换结果后再返回。考虑获取 10,000 行电子表格：不用代码执行时所有行流经上下文；用代码执行时，agent 在执行环境中过滤，只看到 5 行而不是 10,000 行。

类似模式适用于聚合、跨多个数据源的 join、或提取特定字段——都不会膨胀上下文窗口。

### 更强大且上下文高效的控制流

循环、条件和错误处理可以用熟悉的代码模式完成，而不是链接单个工具调用。这比在 agent 循环中交替 MCP 工具调用和 sleep 命令更高效。

### 隐私与安全

当 agent 使用代码执行与 MCP 时，中间结果默认留在执行环境中。Agent 只看到你明确 log 或返回的内容，意味着你不想与模型分享的数据可以流经工作流而永远不进入模型的上下文。

对于更敏感的工作负载，agent harness 可以自动对敏感数据进行 token 化。真实的邮箱地址、电话号码和姓名从 Google Sheets 流向 Salesforce，但永远不通过模型。

### 状态持久化

代码执行加文件系统访问允许 agent 跨操作维护状态。Agent 可以将中间结果写入文件，使其能恢复工作和跟踪进度。Agent 还可以将自己的代码持久化为可复用函数——这与 **Skills** 的概念紧密相关。

注意代码执行引入了自身的复杂性。运行 agent 生成的代码需要安全的执行环境，配备适当的沙箱、资源限制和监控。代码执行的好处——减少 token 成本、降低延迟、改进工具组合——应与这些实现成本权衡。

---

## 结论

MCP 为 agent 连接到许多工具和系统提供了基础协议。然而，一旦连接了太多服务器，工具定义和结果可能消耗过多 token，降低 agent 效率。

虽然这里的许多问题感觉新颖——上下文管理、工具组合、状态持久化——但它们在软件工程中有已知的解决方案。代码执行将这些成熟模式应用于 agent，让它们使用熟悉的编程构造更高效地与 MCP 服务器交互。
