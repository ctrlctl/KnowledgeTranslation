## 开场：为什么 Agentic AI 需要重新思考预训练 [00:00]

很长一段时间以来，我们都在用静态 benchmark 来衡量预训练。如果我们想让这些模型作为 agent 有用，它们需要能跟环境交互。当我们开始关心这些 agentic 任务时，预训练需要从根本上重新思考。这不仅仅是一个 post-training 问题——要在下一代模型中实现我们想要的这组能力。而且衡量这种智能所需的 benchmark 有时今天还不存在。

大家好，欢迎来到 TwiML AI Podcast 的又一期节目。我是主持人 Sam Charrington。今天的嘉宾是 Akansha Choudhury，她是 Reflection 的技术人员。

Akansha，你有非常有趣的背景。你训练过一些最早的大语言模型，包括 PaLM 和 Gemini 1.0、Gemini 1.5。跟我们讲讲那些经历。

我在 Google 进入大语言模型领域，当时在构建一个分布式系统，最终用于训练大语言模型。它有 5400 亿参数。之后人们就不再公布参数数量了。我想知道为什么。

这让我站在了预训练的前沿，一个接一个地解决随规模而来的问题。在前两代 PaLM 模型和前两代 Gemini 模型中，我学到的一件事是：**在规模上，每个问题都会放大，栈的每个可能部分都会出错**。所以总是很有趣，总是很刺激。

你说你在基础设施方面？我不只在 ML 方面，两边都做过。预训练的一个超级有趣的事情是你有很多不同的工具可以用来帮助解决问题。另一件事是你必须能跨栈思考。否则，如果你要训练两到两个半月的东西，你需要能思考系统的每一个部分。

## Reflection 的使命：构建前沿开放 Agentic 模型 [02:27]

Reflection 的使命是为 agentic 能力构建前沿开放智能。公司一直专注于为 agentic 任务构建 post-training 栈。随着最近的融资，我们在做端到端训练——构建既在内部预训练又在内部 post-train 的前沿开放 agentic 模型。

这就是我们今天要讨论的重点——你认为不同的预训练方法是关键的一些原因。

我真正想说的是：很长时间以来，我们在静态 benchmark 上衡量预训练——比如 GSM 8K 或数学奥林匹克问题。但如果想让这些模型作为 agent 有用，它们需要能跟环境交互，在我们能使用它们的工作流中对我们有用。

我们已经开始看到的最简单版本是 **coding agent** 和 **deep research agent**。Coding agent 非常有用——你可以让它帮你理解大型代码库，或者帮你跨多个文件重构和应用修复。它们还不完美。Deep research agent 方面，我觉得我们从搜索栏界面转向了"这是你想要的"，然后让语言模型去找多篇文章来调查那种工作流。

你可以想象任何这样的目标导向任务都可以交给语言模型，模型可以通过多个步骤实现这些目标，而不只是做聊天机器人。这些就是我们开始关心的 agentic 任务。当我们开始关心这些任务时，**预训练需要从根本上重新思考**。

## 为什么不能只靠 Post-Training？ [05:04]

也许要强调这一点：过去三年自 ChatGPT 以来的很多增量进展——无论是推理、工具使用——所有这些贡献于我们构建"agentic 系统"能力的东西，都不是来自对基础 LLM 预训练方式的根本不同思考，而是通过添加新的微调或 post-training 方式（通过强化学习和其他技术）。

为什么我们不能继续这样做？

完全可以继续。但我认为它在根本上限制了你能实现的能力。我思考模型的方式是：它们能做什么？能力可以是任何东西——有没有长上下文能力？能不能在更长上下文上做检索？擅不擅长自然语言理解/生成？擅不擅长推理？

对于 agentic 任务（如编码任务）特别重要的是：如果你在读代码库然后执行某些部分或写自己的代码，你会随时间积累上下文。如果你执行了什么，还有来自执行的额外反馈。

所以你需要模型能够：**规划**作为一种能力、能在可能很长的上下文长度上**推理**、能从失败的轨迹中**恢复**、能在运行中**学习新工具**。

所有这些在某种程度上是可能的，但有时受限。根本问题是**上下文工程问题**。今天公司构建 agentic 系统时，做大量上下文工程——字面上受限于"我能塞进上下文长度的就是这些"。

什么给了你信心，认为只改变预训练就能实现你的目标？我们需要更根本的改变吗——新架构、后 transformer 方法？

当我谈论重新思考预训练时，我总是从"我们想从模型中获得什么能力"来思考。对我来说，架构只是方程的一部分。很大一部分是**损失目标**和**训练数据**。

## Attention 机制需要如何演进 [08:25]

我们想要的是模型能做多步规划和推理，看它们之前在上下文中做了什么，用那个来指导下一步行动。要做到这一点，transformer 中实现这个的基本机制是 attention 机制。

Attention 机制在长上下文上是否工作良好——这是我们正在非常认真审视的问题。我们知道长程检索（比如在百万上下文上检索）今天用 LLM 是可以实现的。**在更长上下文上推理是一个更难的问题。**

第二个极其重要的是训练数据。第三个是损失目标。信不信由你，我们实际上训练这些模型来概率性地预测下一个 token。从中我们让这些模型成为了极强的推理者。但这是最好的损失目标吗？

我押注的是：我们需要这些模型有更根本的长程推理能力，需要能从上下文中学习如何学习。

你不相信我们需要 state space model 或某种新一代的东西？你骑着你有的马？

是的。而且我要补充，你必须经历过多代模型的预训练经验才能知道在哪里最好地利用数据。预训练是一门既有趣又刺激、高风险高资本支出的科学。当你做那些赌注时，你想尽可能确定。这就是为什么**预训练看到最多增量变化，而 post-training 看到更激进的变化**。

有很多有趣的提议架构，研究者把 scaling 留给别人因为他们没有资源。但在规模上是否能看到预期结果仍是一个大问题。对有 scaling 经验的人来说，这真的是一门艺术和科学。

## 损失函数调整与 Agent 性能 [16:08]

你能详细说说损失调整如何直接关联到 agent 性能吗？

过去做的一些事情：训练编码模型做自动补全时，我们不只是给它们代码文件然后训练 next token。我们有 **fill-in-the-middle**——实际上把文件拆开，把前半或后半放前面，中间部分放最后，模型必须预测那个。

训练工具使用时，我们实际上 mask 掉某些部分，让模型学习用哪个工具。所以不只是关于哪个搜索查询——那些方面在训练中被 mask 掉了。

如果你回顾语言模型历史，比如 BERT，masked language modeling 是一个被大量探索和利用的目标。

所以从损失角度看，你在损失目标中关注什么也很重要。Masking 是一种特定方式，训练如何被增强是另一种方式——让模型关注每个序列中的特定部分。

听起来你说的是：很多我们在 post-training 中做的事情还没有以新的预训练方式进来，但正在找方法把 post-training 中做的一些事情以可扩展的方式拉入预训练，使它们成为模型更根本的能力。

是的。我会说它统一了两个范式。Pre 和 post 根本上来自这样一个世界：我们必须从预训练开始，因为那是 scaling 给我们最大收益的地方。而 post-training 让我们把这些模型变得更可用作聊天机器人。

当我们进入 agentic 范式时——推理是你想在最后阶段赋予模型的能力，还是它应该前移？我们是否需要两个范式之间非常严格的划分？这是一个很好的问题。

## 训练数据：质量、推理轨迹与合成数据 [19:36]

从训练数据角度，你觉得需要怎么演进？

预训练模型根本上依赖于大量高质量、多样化的数据。我们最多利用的是尽可能多的规模——更多数据总是更好。尽可能多样化的数据源。

从东方同行那里（Qwen、DeepSeek、Kimi 模型），我觉得训练数据的**策展质量**也很重要。这是一个轴，当你让训练数据极高质量时，你能从预训练模型中获得更多计算效率。

第二个重要的轴是推理。怎么获得真正好的推理轨迹？就像在问：如果你在互联网上训练，推理默认会涌现，但怎么获得人们在所有可能领域解决问题的专家轨迹？

今天我们通过让模型在强化学习环境中探索来做。但一旦我们对模型如何生成这些轨迹有了一些理解，什么应该被放入、什么在规模上可用于预训练就成了一个问题。

推理轨迹的 token 量跟核心训练数据的 token 量相比——差好几个数量级，是总训练数据的很小一部分。如果它被 Reddit 闲聊淹没了，你怎么让它在训练过程中产生影响？

这是一个公平的观点。值得问的问题是：主导的预训练数据源是什么，如何增强它来生成那种量的数据？比如主导训练数据源是互联网文章。怎么用互联网文章但以有趣的方式增强它们——有结果表明你可以把它们转化为问答对、对话形式、或以有趣方式增强问题解决任务。

你必须利用基本的数据量来生成类似量的数据，然后才能走完全新的生成数据源的路。

这听起来很贵。DeepSeek 训练了 15 万亿 token。假设 Gemini 是几十万亿 token。如果你做的是每百万 token 不到一美元的推理加上某个小倍数……也许不那么贵。

对于合成数据的"吸自己尾气"问题——如果你大幅改变分布为全合成生成的，我预期模型不会表现好。目标是保持底层数据分布非常代表你想让模型训练的自然数据分布。

## Benchmark 构建与能力衡量 [26:01]

Benchmark 的有趣之处是每年出几个新的，然后被饱和，然后你得建新的。对于前沿开发，当前范式是每个人在内部建 benchmark 来衡量他们追求的模型能力。

我们想要的是：模型能更好地推理、在上下文上做长程推理、做多步问题、从失败轨迹中恢复、更好地规划、学习如何使用工具。所有这些能力需要非常具体的衡量方式。

我们开始看到一些不同时间跨度的任务出现。比如 METR 有 software atomic actions，允许你有不同长度的任务。你基本上想要不同复杂度、沿这些能力维度变化的任务来测试模型。

就像把你一天中的真实工作流分解——模型能解决哪些子问题？即使那些很难，为什么难？把那个变成模型的挑战——大致就是很多 benchmark 的构建方式。

## 长程推理：两种形式 [33:33]

**第一种形式**：比如你想让 AI 理解你的整个代码库，包括另一个团队写的部分。长程推理允许你引用代码库的那部分并像库一样使用它，因为 AI 能帮你无缝理解和使用。

这大致意味着：如果你把很多东西放在上下文长度中，模型能推理关于在上下文长度中位置相距很远的东西。检索相关部分是更容易的问题（needle in a haystack）。但多跳推理 benchmark（如 MRCR V2 或 Loft）只是最近才开始显示模型在变好的信号。即使你有百万 token 上下文长度，你不一定能思考所有内容。

**第二种形式**：轨迹方面的长程推理。当你想让模型做多步推理时，你实际上在要求模型提前思考——像下棋一样。下一个行动应该让你朝目标移动。这个能力之前不存在，因为逻辑上只是生成下一个 token。

模型今天经常陷入重复循环，因为它们不真正知道自己犯了错误。所以它们会再去尝试同样的事情。

## 从失败中恢复与工具学习 [38:09]

当你收集轨迹——这是相关上下文、这是我的解决方案、这是我尝试的、这是执行反馈——你会发现模型可能需要在多步中弄清楚从上一步学到的什么不应该重做。

这是一个更难的问题：部分是强化学习问题（需要选择新的动作空间），也是预训练问题（模型在关注什么？它理解这些是失败步骤吗？轨迹是否以正确格式呈现让它注意到需要纠正？）

我们想让模型**学习如何学习和如何自我纠正**。

关于幻觉——取决于业务目标，幻觉是正面或负面的词。如果这些失败是模型认为某事为真但实际不是——模型没有那个意识——你怎么给模型那个意识？如果我们能做到，我们不就修复了幻觉吗？

我把幻觉看作概率上最高概率的下一组 token。问题是：有没有其他东西可以进入上下文，或者通过跟工具交互获得额外反馈来改变方向？

关于工具学习——MCP 立刻浮现在脑海。MCP 的戏剧性：MCP 是好东西→MCP 炸了上下文→让 agent 写软件程序来代替→那很难→让 agent 搜索它的工具。如果有什么东西需要更根本的解决方案，也许就是工具使用和 agent 学习新工具的能力。

我们到目前为止教模型学到的是：放在上下文中的就是它们知道的。如果我们能指向 N 个工具，通过交互让它们学习这些工具有用还是没用——这在过去以容器学习或机器人领域的模仿学习形式被尝试过。

问题回到：怎么让模型元学习——学习如何学习新环境中探索的确切格式，使模型学会在那个空间中采取行动。一个有前途的方向是某种统一的领域特定语言，也许是代码格式，允许这种推理涌现。

## 编码 Agent 的原则是否适用于其他工作流 [46:45]

你为编码 agent 产生的想法在多大程度上适用于工作流 agent——企业工作流或消费者工作流？

即使在构建编码 agent 时，同样的原则适用，只是稍微更广泛。在预训练规模上我们获得的一个根本能力是模型学会**跨模态推理**——跨语言、跨代码和文本、跨代码中的不同语言。

根本原则仍然非常适用。主要是 post-training 的最后阶段会不同，但模型需要能跨域推理。

## 总结与招聘 [48:28]

来跟我们一起工作吧。我们在招人——跨预训练和 post-training。我们最近完成了由 NVIDIA 支持的创始轮融资。我们是一个约 60 人的研究团队，希望为开放 agentic 模型构建前沿实验室。团队成员来自 DeepMind、OpenAI、顶尖大学，在 PaLM、ChatGPT、Gemini、AlphaProof、AlphaGo 中有领先贡献。

如果你想在社区中产生影响，很多工作从构建好的衡量系统开始。我谈到的很多能力没有真正强大的 benchmark 来衡量。最好的起点是：找到当前模型不擅长的地方，理解为什么，创建评估 benchmark。

从那里你可以从 post-training 开始——这是相对便宜的尝试。如果那让你兴奋，就来加入我们或任何前沿实验室，承担从头构建这些模型的更大冒险。
