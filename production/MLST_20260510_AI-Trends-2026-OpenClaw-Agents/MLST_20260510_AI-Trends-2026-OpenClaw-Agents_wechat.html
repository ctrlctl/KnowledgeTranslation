AI Trends 2026：OpenClaw、推理与 Agent

宏观回顾：一年来的变化 [00:45]

Sebastian Raschka 是独立 LLM 研究者。与一年前相比，几乎是 DeepSeek 的周年纪念——V3 模型伴随 R1 推理模型发布，可以说是"推理革命"。仍然是 LLM、仍然是同样的基础模型，但现在有了更多技术让模型在解决复杂问题时更聪明。

架构上，LLM 架构看起来仍然非常相似。两个主要变化：

1. 推理训练（reasoning training）：新的后训练技术 2. 工具使用（tool use）的更重度聚焦：以前 LLM 从记忆中回答所有问题，但这不总是最有效或准确的。就像人类——如果你问我一个复杂的数学题，我会拿出计算器。LLM 现在也越来越多地使用工具，这能降低幻觉率、提高准确性

· · ·

实际使用：LLM 的日常工作流 [04:50]

2026 年已经有大量新闻：Opus 4.6、OpenAI 5.3、OpenClaw/Multbot。

Sebastian 的观察：如果你把最好的开源 LLM 放进 ChatGPT 或 Claude 的界面，你几乎能得到同样质量的表现——很多用例现在围绕 LLM 周围的工具包装器演进。这就是去年末流行的 harness engineering 概念。

个人使用方式：主要用于校对、检查、小型便利任务。比如上传 PDF 让它提取目录标题。

编码方面：以前用 VS Code 多年，现在 LLM 作为插件——不必是前台中心，可以是小助手。"第二双眼睛"但不完全接管。你仍然需要问对问题、仍然需要跑实验验证。

新的 Codex 插件/应用的进步：以前要手动上传代码文件再手动整合反馈。现在更原生——能看到 file diff、不用离开编码环境、可以给 LLM 访问整个 git 文件夹、LLM 能自己运行工具（单元测试等）。没有单一突破性变化，但所有这些小事加起来让 LLM 更有能力。

推理努力的改进：半年前要好结果几乎总得用最高推理模式（等很久）。现在即使较低模式也相当好——中等推理努力对大多数任务就够了。LLM 自己也越来越擅长判断需要多少努力——auto 模式越来越好用。

OpenClaw 与 Agentic 工具 [14:23]

OpenClaw（原 Multbot）是一个本地 agent，人们可以在自己电脑上运行。它让人兴奋——类似当年 AlphaGo 让不玩围棋的人也兴奋起来。有真实用例（组织日历和邮件），但 Sebastian 个人还有信任问题——不太信任它处理财务或日历。

作为展示 LLM 能做什么的演示，它很酷。但两人都没有在日常中大量使用 OpenClaw 或任何特别花哨的 agentic 工具包装器。

· · ·

用 LLM 构建确定性工具 [16:35]

两人都发现 LLM 最大的价值之一是用 LLM 开发确定性工具——LLM 不做日常任务，而是开发做任务的工具。

Sebastian 的例子：

  • 用 LLM 学 Swift 开发原生 macOS 应用（给播客添加章节标记的工具）
  • 从社交媒体书签中提取论文标题/日期/作者的工具
  • 体育预测项目中用 LLM 处理球员名字拼写不一致的问题

关键洞察：如果任务是确定性的，仍然应该开发确定性工具——用 LLM 来开发它，但不必每次都用 LLM 来执行。"如果你只有锤子，一切都变成钉子"——要认识问题的本质，选择最佳工具。

LLM 特别适合的场景：需要类似人类的、非结构化的方法时——比如模糊的数据集解析、名字匹配（有口音、中间名不一致等）。

· · ·

模型的渐进式改进 [11:01]

对 Sebastian 来说，新模型更多是渐进式改进——更健壮、更好，但没有"哇"效果。逐渐发展出对结果的更多信任。

关于社交媒体上的"one-shot"声称：Sebastian 的经验是即使简单的 macOS 应用也需要多次迭代才能让所有按钮正确工作。可能是指令不够明确，可能是运气好的案例——但"one-shot"不反映今天的实际工作方式。

中间地带很重要：不是完全不用 LLM，也不是完全依赖 LLM（纯 vibe coding）。仍然值得学习编程和数学——让你更高效地使用 LLM。例子：用 LLM 给网站加暗色模式，但按钮对齐不对时，直接去 CSS 文件调整比反复 prompt LLM 更高效。

2026 年的三大主题 [29:42]

1. 推理（reasoning）：继续推进后训练的推理前沿 2. 推理时扩展（inference scaling）：更复杂的技术，部分与训练相关但主要是训练后如何使用 LLM 3. Agentic 使用：LLM 作为循环运行，公司会加倍投入优化这个循环

· · ·

推理训练的进展 [31:06]

2025 年最大进展：OpenAI O1 让所有人兴奋，然后 DeepSeek R1 发布了推理 pipeline——真正起飞了，很多公司跟进。但仍然非常新——只有一年历史。

Sebastian 最近为一章内容编译了 15 种不同的改进和调整：从基本的序列级 log probs 改为 token 级，到 NVIDIA 的 GDPO 等。

研发重心转移：预训练仍然是训练 pipeline 中最大的部分（数据量大、非常昂贵），但研究团队的焦点更多在后训练——因为这是更新的范式，仍有低垂果实可摘。预训练已经相当成熟，你仍然可以用更多数据、优化数据混合、multi-token prediction 来改进，但最有趣的事情在后训练的推理领域。

· · ·

可验证奖励 [33:21]

推理训练本质上主要基于可验证奖励（verifiable rewards）——有些任务你可以验证答案。

在 DeepSeek R1 中，可验证奖励是编码和数学：

  • 数学：让模型以 boxed 格式输出最终答案，用确定性代码提取，用 Wolfram Alpha 或 SymPy 符号化比较
  • 编码：确保代码能编译

这很棒因为你可以无限评估答案——让 LLM 生成 60,000 个答案，在很短时间内计算所有奖励。不像 RLHF 需要人类反馈。

扩展方向：

  • 格式奖励：训练模型输出特定结构（如 think 标签）
  • 过程奖励模型（process reward model）：评估推理解释而不仅是最终答案。DeepSeek R1 原论文列为失败尝试（增加 reward hacking 风险），但 DeepSeek Math 3.2 用多层评估（评估器的评估器）成功了

能否扩展到数学和编码之外？ 可能——比如药物设计或蛋白质结构建模，有物理约束可以作为验证。最坏情况可以训练另一个模型提供正确性奖励，但容易 reward hacking（类似 GAN 中生成器崩溃的问题）。

推理时扩展 [42:19]

推理时扩展的定义：训练后、推理时花更多计算来获得更好性能。

两种形式： 1. 顺序：推理模型本身就是一种——生成比普通模型更多的 token（解释更长），帮助到达正确答案 2. 并行（self-consistency）：用不同温度设置让 LLM 多次回答同一问题，然后多数投票或用评分器选最佳答案（也叫 best-of-n）——本质上是经典集成技术

Self-refinement：让 LLM 生成答案，然后把答案喂给另一个 LLM（或自己），用 rubric 检查，生成报告（弱点、不一致等），再把报告喂回原始 LLM 让它改进。DeepSeek Math 3.2 用更复杂的 self-refinement（第三个模型评估评估器）展示了从普通水平到数学竞赛金牌水平的提升——同一个模型，只是加大了推理时扩展。

注意：self-refinement 有时也会让答案变差——过度思考或反馈有误。不是万无一失的技术。

开源生态中还不太流行——GPT OSS 模型可以在 system prompt 中设置推理努力，但没有自动的 self-consistency 或 self-refinement。

Agentic 使用的现状与未来 [51:01]

Agentic 的定义（本次对话中）：在循环中运行的东西。

例子：Codex 或 Claude Code 做多次迭代解决问题——不是 one-shot，而是执行任务。最近 Claude Code 和 GPT 5.3 Codex 添加了可以调度定期任务的功能。

Multi-agent 系统：Sebastian 个人没有深入探索。他认为 LLM 本身不是瓶颈——更多是上下文工程问题：如何把结果提供给另一个 LLM。类似图像/视频生成中一个 LLM 解析文本然后传给扩散模型。

关键挑战：每个 LLM 都有自己的失败率。模型越多、互相依赖越多，其中一个失败的风险越高。改进模型本身是改进整个系统的主要方式。

未来方向：目前 API 中的 LLM 还是通用的，没有专门为 multi-agent 交互训练。如果为 multi-agent 设置准备训练数据（类似 Codex 是从 GPT 5.2/5.3 fork 出来专门为 Codex 应用训练的），可以获得更好性能。预测 Claude 和 OpenAI 会关注 OpenClaw 在做什么，推出自己的版本——因为他们控制模型，可以为交互式 multi-agent 环境微调。

LLM 架构的演进 [58:57]

从 2025 到 2026 年 2 月，没有根本性的架构变化推动 SOTA。

主要进展：

  • Mixture of Experts（MoE）：DeepSeek V3 后真正流行，很多公司采用（Kimi 从 670B 扩展到 1T 参数，Mistral 也用了 DeepSeek V3 架构）
  • Multi-Head Latent Attention（MLA）：压缩 KV cache——投影到更小的压缩状态，推理时重建。本质上是用计算换内存（类似 LoRA 的低秩投影）
  • DeepSeek Sparse Attention：用"闪电索引器"选择性地关注 token 子集，使注意力亚二次扩展
  • Qwen 3 Next：混合注意力机制 + Gated Delta Net（状态空间模型方法），但不是旗舰模型——是并行尝试

关键观察：大多数公司不赌博——拿有效的东西，在数据和算法上做差异化。但可能 2026 年某个旗舰模型会有根本不同的方法。

文本扩散模型：Google 计划推出——不是顺序生成文本，而是像 BERT 一样有 mask 然后逐步去噪。可能更便宜更快，适合免费层或 Google 搜索摘要。

持续学习的挑战 [01:05:37]

持续学习可能是"最大的梦想"——让模型自我改进。但目前没有可靠的路径。

现实中的"持续学习"更像是半自动的：收集最近的数据，仔细更新模型。不是完全自动的，因为： 1. 资源约束：不可能每个用户一个模型副本 2. 安全性：随机更新可能让模型变差，影响所有人

长上下文是否缓解了需求？部分是——200 页 PDF 可以直接放进上下文，不需要 RAG 或微调。但只能走这么远——你作为用户得知道提供什么信息。结合工具使用（web 搜索）可以处理数据截止后的事件，但如果事件有很多连锁影响，工具调用只能获取某些事实，不能获取与其他数据点的全部交互。
