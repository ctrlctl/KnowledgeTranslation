30 倍增长背后的驱动力 [00:37]

Baseten 过去一年增长了 30 倍，预计今年收入超过 10 亿美元。Tuhin 认为驱动力来自三个方面：

1. 开源模型跨过了能力门槛——不再是玩具，而是可以在生产中替代闭源 API 2. RL 后训练变得主流——有足够多的成功案例证明专用模型的价值 3. 企业开始"拥有"自己的推理——长尾模型回到客户手中

但按推理量算，99% 的企业市场还没上线。大部分企业采用仍在前方。

· · ·

应用层为什么会存在 [02:04]

面对"前沿实验室会不会吃掉一切"的问题，Tuhin 的回答：

关键不在模型本身，而在只有你能获取的用户信号。以 Abridge（医疗记录 AI）为例：临床医生对笔记的编辑、EMR 中后续三步的工作流——这些信号前沿实验室根本接触不到。拥有这些信号的公司可以在此基础上做后训练，建立护城河。

类似的还有客服场景：一个工单不是一次性完成的，通常涉及 10-20 个动作。这种多步工作流才是专用模型的用武之地。

95% 的 token 来自定制模型 [13:20]

Baseten 有三条业务线：专属推理（dedicated）、共享推理（shared）、训练。

95% 的 token 跑在专属推理上，而且几乎所有客户都对模型做了修改——不只是质量上的微调，还包括性能层面的定制（编译方式、量化策略等）。没有人在跑原始的开源权重。

· · ·

后训练与推理是同一个问题的两面 [15:05]

Baseten 收购了后训练团队 Paz。收购逻辑：

  • 推理和后训练高度耦合——量化时机影响训练方式，训练方式影响推理性能
  • 推理产生数据 → eval → 发现 reward signal → 后训练 → 更好的推理。这是一个闭环
  • 越早介入客户的后训练流程，越能锁定推理需求

Tuhin 的产品论点：推理云的核心不只是跑模型，而是构建推理-后训练的飞轮。

· · ·

算力供给危机的真实程度 [18:47]

"不管你听到多少关于供给紧张的叙事，实际情况比你想象的更糟。"

具体数据：

  • Baseten 跑在 18 个不同的云上，全球 90 个集群
  • 利用率常年在 mid-90%——"令人不安地高"
  • 想要 1024 张 B200？现在需要签 3-5 年合同，预付 20-30% TCV
  • 即使有供给，合格的供应商也很少——大约只有十几家靠谱的云，其中只有三四家是金牌级别

这改变了公司的资本结构思考：低资金成本变成了竞争优势，甚至影响了上市时间表。

推理云的护城河 [24:30]

"GPU as a service 不粘。推理加上软件层极其粘。"

  • 前 30 大客户零流失
  • 年 NDR 约 400%
  • 在算力受限的世界里，拥有算力本身就是资产

护城河 = 软件层（运行时优化、路由、编排）+ 供给获取能力（半天内接入新云）+ 客户关系深度。

· · ·

多芯片世界与 Nvidia 的生态壁垒 [26:10]

Tuhin 认为会有推理专用芯片（decode-specific chips），但短期内 Nvidia 的优势难以撼动：

1. 供应链能力被严重低估 2. CUDA 生态和开发者工具链 3. 对基础设施公司来说，最重要的是移动速度——在 Nvidia 生态内你能最快迭代

其他芯片厂商的问题：如果把 90% 的产能绑定给一个大客户，生态就无法形成。

H100 已经四年半了，价格还在涨。这说明了什么。

· · ·

工作负载的演变方向 [28:22]

Baseten 正在投资的方向：

  • Prefill 和 decode 解耦——作为独立问题分别优化，看到巨大收益
  • KV cache 感知路由——虽然不新，但在规模上持续重要
  • 沙箱——coding agent 需要执行环境
  • 新的投机解码技术——加速推理
  • 异步批量推理——提高利用率的一等公民体验
  • 持续学习闭环——推理 → eval → 后训练 → 更好的推理

· · ·

规模化运营中的意外问题 [31:07]

在极端规模下遇到的问题往往不是 LLM 特有的，而是系统级的：

  • 昨天第一次遇到 kernel panic——因为 fluent bit worker 在一个节点上产生了过多日志
  • 超大规模云（AWS/GCP）的产品也有极限——你真的会撞到
  • LLM 运行时（如 vLLM）其实还很不成熟——KV cache 的使用方式比大多数人想象的更粗糙

最让 Tuhin 焦虑的：算力。没有任何世界里，未来 5-10 年的算力足够释放 LLM 的全部价值。

Jevons 悖论在推理市场的验证 [38:27]

推理成本下降后，客户是用得更少还是更多？

答案明确：更多。

  • Agent 运行时间变长了——因为更便宜，所以可以让它多做几步
  • 开发者的逻辑：如果便宜了，就往更多地方插入智能
  • 客户的逻辑：更多推理 = 更好的答案 = 更好的用户体验 = 更多收入

Tuhin 的判断："即使有了 AGI，剩下的也全是推理。推理是最后的市场。"

没有任何客户表现出"这个答案够好了，不需要更多推理"的迹象。需求会持续增长很长时间。
