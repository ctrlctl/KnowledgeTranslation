AI 精神病：当 coding 变成 manifesting [00:59]

主持：最近几个月 AI 领域非常激动人心。我记得有一天走进办公室，你说你必须每天 16 小时"coding"——或者说 coding 已经不是正确的动词了。

Karpathy：对，我得每天 16 小时向我的 agent 表达我的意志。Manifest。我一直处于这种 AI 精神病状态，因为作为个人能实现的东西有了巨大的解锁。以前你被打字速度瓶颈住了，但现在有了这些 agent——我觉得是去年 12 月某个东西翻转了。我从 80-20（自己写 vs 委派给 agent）变成了 20-80。现在可能比 20-80 还多。我大概从 12 月起就没手动打过一行代码了。

这是一个极其巨大的变化。我跟我父母聊这个，普通人根本没意识到这件事发生了，或者它有多戏剧性。如果你随便找一个软件工程师看他在做什么，他们构建软件的默认工作流从 12 月起就完全不同了。

所以我就处于这种精神病状态——试图搞清楚什么是可能的，把它推到极限。怎么不只有一个 Claude Code 或 Codex session？怎么有更多？怎么恰当地使用这些 claw？

主持：如果你都紧张，我们其他人就更紧张了。我们有个团队，所有工程师都不手写代码，他们都对着麦克风，一直在对 agent 低语。最奇怪的工作环境。我以为他们疯了，现在我完全接受了——他们只是走在前面。你怎么看自己现在的能力边界？

Karpathy：我觉得很多东西，即使不 work，你也觉得是 skill issue。不是能力不在那里，而是你没找到把现有东西串起来的方式。我没给 agents.md 写够好的指令，或者没放一个够好的 memory 工具进去。所以当它不 work 的时候，感觉都是 skill issue。你想看怎么并行化它们。你想成为 Peter Steinberger。

Peter 很有名——他有张照片，面前一个显示器上跑着很多 Codex agent。如果你 prompt 正确并用 high effort，每个大概跑 20 分钟。他有 10 个 repo checkout，就在它们之间切换分配工作。你可以用更大的宏操作来移动——不是"这里一行代码、这里一个函数"，而是"这里一个新功能，给 agent 1；这里另一个不会冲突的功能，给 agent 2"。然后尽你所能 review 它们的工作。另一个 agent 在做研究，另一个在写代码，另一个在做实现计划。一切都以宏操作的形式发生在你的代码仓库上。

Token 吞吐量就是新的 GPU 利用率 [05:07]

Karpathy：我的直觉是：每当我在等一个 agent 完成什么，显然我可以做更多工作。如果我有更多 token 可用，我就应该并行化任务。这非常有压力——如果你不觉得被 token 花费限制住，那你就是系统中的瓶颈。如果你的订阅还有剩余，那就意味着你没有最大化你的 token 吞吐量。

我读博时就有过这种体验——当 GPU 没在跑的时候你会紧张，你有 GPU 算力但没最大化可用的 FLOPS。但现在不是关于 FLOPS，而是关于 token。你的 token 吞吐量是多少？你指挥多少 token 吞吐量？

主持：有意思的是，至少 10 年来很多工程任务里人们不觉得受计算限制。现在整个行业都觉得受资源限制了。

Karpathy：对，是 skill issue——这很赋能，因为你可以变得更好。所以它很上瘾，因为你变好的时候有解锁。

主持：如果你迭代一年达到精通，会是什么样？

Karpathy：大家都在试图往上走。不只是单个 agent session，而是多个 agent、它们怎么协作、团队等等。然后 claw 也是一个有趣的方向——它把持久性带到了全新的层次。它不是你交互式参与的东西，它有自己的小沙箱，代你做事即使你不在看。还有更复杂的 memory 系统——OpenClaw 的 memory 比默认的（只是上下文满了做 compaction）复杂得多。

OpenClaw 与 Claw 的五个创新 [07:06]

主持：你觉得是 memory 还是更广的工具访问让 OpenClaw 对用户产生共鸣？

Karpathy：我觉得至少有五个东西同时共鸣。Peter 做了非常出色的工作，他同时在五个不同方向创新并把它们整合在一起。

首先是 soul document——他真的精心打造了一个引人入胜的人格。很多当前 agent 没做好这一点。Claude 有不错的人格——感觉像队友，和你一起兴奋。Codex 的 coding agent 则很干巴巴——它不关心你在创造什么。

Claude 的谄媚度调得相当好——当 Claude 表扬我时，我确实觉得我稍微值得。当我给它一个不太成熟的想法时，它不会反应很强烈。但当是一个真正好的想法时，它确实会多奖励一点。所以我觉得我在试图赢得它的表扬——这很奇怪。人格真的很重要。

然后是 memory 系统，还有他就是在玩得开心，还有单一 WhatsApp 入口连接所有自动化。

Dobby：用 Agent 接管智能家居 [09:25]

Karpathy：一月份我经历了一段 claw 精神病期。我建了一个 claw 来管理我的家，叫 Dobby——家养小精灵 claw。

我用 agent 找到了家里局域网上所有的智能家居子系统。我告诉它"我觉得家里有 Sonos，你能找到吗？"它做了 IP 扫描，找到了 Sonos 系统——没有密码保护，直接登录了。然后它逆向工程了 API，问我要不要试试。我说在书房放点音乐——音乐就出来了。三个 prompt 就从"你能找到我的 Sonos 吗"到音乐在播放。

灯光也一样。它基本上黑进去了，搞清楚了整个系统，创建了 API，创建了仪表盘让我看到所有灯光的控制中心。我可以说"sleepy time"，所有灯就关了。它控制我的灯光、暖通、窗帘、泳池和水疗，还有安防系统——外面有摄像头，有人来的时候先做变化检测，然后送给 Qwen 模型看视频，再通过 WhatsApp 发短信给我："FedEx 卡车刚到，你可能有快递。"

以前我用六个完全不同的 app，现在 Dobby 用自然语言控制一切。

软件的未来：API 优先，Agent 是胶水 [11:48]

主持：这是不是说明了人们从用户体验角度真正想要什么？

Karpathy：某种程度上是的。人们脑中的"AI 应该是什么样"和 LLM 的原始形态不一样。LLM 是 token 生成器，但人们想的是一个有身份的实体，你可以告诉它事情，它记住，它就在 WhatsApp 背后。这更容易理解。

主持：你把六个软件系统统一了——这是不是说人们其实不想要我们今天的所有软件？

Karpathy：对。这些 app store 上的智能家居 app 某种意义上不应该存在——应该只是 API，agent 直接使用。LLM 可以驱动工具、调用所有正确的工具、做相当复杂的事情。所以也许有大量定制 app 的过度生产，它们不应该存在，因为 agent 把它们揉碎了。一切应该更多地只是暴露 API 端点，agent 是智能的胶水。

行业必须在很多方面重新配置：客户不再是人类，而是代表人类行动的 agent。这个重构会相当大。

现在还需要一些 vibe coding，我在看着它、和系统一起工作。但我觉得一两年后这些会是免费的、trivial 的、table stakes。即使开源模型也能做到。barrier 会降下来，变成代你运行的临时软件。

AutoResearch：把自己从循环中移除 [16:21]

主持：AutoResearch 的动机是什么？

Karpathy：我之前发了条推说：要从现有工具中获得最大价值，你必须把自己从瓶颈中移除。你不能在那里 prompt 下一步。你需要把自己拿到外面，安排好让一切完全自主。怎么最大化你的 token 吞吐量而不在循环中？这就是目标。

游戏的名字是增加你的杠杆——我只偶尔投入很少的 token，大量的事情代我发生。

AutoResearch 就是这个的一个含义：我不想做循环中的研究者，看结果什么的。我在拖系统后腿。问题是：怎么重构所有抽象，让我只需要安排一次然后按 go？

主持：你对它的有效性感到惊讶？

Karpathy：对。我有 DataChat 项目——很多人对我痴迷小 GPT 模型感到困惑，但对我来说训练 GPT 模型只是训练 LLM 的小 harness、小 playground。我更感兴趣的是递归自我改进——LLM 改进 LLM 能到什么程度。所有前沿实验室都在做这个。

我已经用传统方式把 NanoChat 调得相当好了——两十年的经验，做了大量实验、超参数调优。然后我让 AutoResearch 跑了一晚上，它回来的调优是我没看到的。对，我确实忘了 value embedding 的 weight decay，我的 Adam beta 没充分调优。而且这些东西联合交互——调了一个，其他的可能也要变。

我不应该是瓶颈。我不应该在跑这些超参数优化。我不应该在看结果。有客观标准的情况下，你只需要安排好让它永远跑下去。

这只是单线程的 AutoResearch。前沿实验室有几万张 GPU 的集群。很容易想象怎么在小模型上做大量这种自动化，然后外推到大模型。

Program.md 的元优化 [21:00]

主持：什么时候模型会写出比你更好的 program.md？

Karpathy：Program.md 是我描述 auto researcher 应该怎么工作的蹩脚尝试——做这个、然后那个、试这些想法。我用 Markdown 写的。

你可以想象不同的 program.md 会给你不同的进展。每个研究组织本质上都由 program.md 描述——一组 Markdown 文件描述所有角色和连接方式。你可以想象有更好的研究组织——也许它们早上少开站会因为没用。这都只是代码。一旦有了代码，就可以想象调优代码。

主持：我的竞赛想法是：让人们写不同的 program.md，同样的硬件，看谁改进最多。然后把所有数据给模型，让它写更好的 program.md。

Karpathy：100% 可以做到。你可以看改进从哪来，然后改 program.md 让更多这类事情发生。这种元优化完全可以想象。

LLM 部分现在被视为理所当然。Agent 部分被视为理所当然。Claw 实体被视为理所当然。现在你可以有多个、可以有指令、可以对指令做优化。这就是为什么精神病——因为这是无限的，一切都是 skill issue。

Agent 的锯齿感：RL 的边界 [24:13]

Karpathy：有几个 caveat。第一，AutoResearch 极其适合有客观可验证指标的东西。比如写更高效的 CUDA kernel——你有低效代码，想要行为完全相同但快得多的代码。完美契合。但很多东西不是这样——如果你不能评估它，就不能 auto research 它。

第二个 caveat：整个东西还在接缝处爆裂。如果你试图走太远，整体实际上 net 没用。

我同时觉得我在和一个极其聪明的博士生（一辈子的系统程序员）以及一个 10 岁小孩对话。这种锯齿感（jaggedness）非常奇怪。人类的能力更耦合——你不会遇到这种组合。Agent 的锯齿感大得多：有时候我要个功能，它回来的东西完全错误，然后我们进入完全错误的循环。

主持：为什么会这样？

Karpathy：根本原因是这些模型通过强化学习训练。实验室能改进任何可验证的东西——代码写对了吗？单元测试过了吗？是或否。但它们在更软的东西上挣扎——比如我意图的细微差别、什么时候该问澄清问题。

你要么在轨道上——是超级智能电路的一部分——要么不在轨道上，在可验证领域之外，一切就开始漫游。

比如你去最先进的模型问"讲个笑话"——你知道会得到什么笑话吗？"为什么科学家不信任原子？因为它们组成了一切（make everything up）。"这是三四年前的笑话，今天还是这个笑话。即使模型已经巨大改进了——你给它 agentic 任务它能跑几小时为你移山——但你问个笑话，还是五年前的烂笑话。因为它在 RL 之外，不在被改进的范围内。

主持：这是不是意味着我们没看到泛化——笑话聪明度和代码聪明度没有关联？

Karpathy：对。有些东西可验证，有些不可验证。有些被实验室任意优化了，有些没有。有研究组声称如果你在代码生成上更聪明，应该在所有事情上都更好。笑话的情况表明这没有发生。我不认为这在发生。

模型的物种分化 [28:58]

主持：如果这种锯齿感持续存在，把所有东西打包在单一模型里有意义吗？还是应该拆分成可以在不同智能领域优化的东西？

Karpathy：目前实验室在试图有一个单一的、在所有领域普遍智能的模型，把一切塞进参数里。但我确实认为我们应该期待更多物种分化（speciation）。动物王国的大脑极其多样——有很多不同的生态位。有些动物视觉皮层过度发达。

你不需要一个无所不知的 oracle。你让它物种分化，放到特定任务上。应该能有更小的模型，仍然有认知核心、仍然胜任，但然后专精——在你真正关心的特定任务上变得更高效。

但我不觉得我们已经看到太多物种分化。目前是模型的单一文化。微调而不丢失能力的科学还没完全发展——我们还没有除了 context window 之外真正操作智能的原语。Context window 就是 work 而且操作成本低，所以我们通过它获得定制。但更深层地调整模型——持续学习、在某个领域变好、真正触碰权重而不只是 context window——要棘手得多，因为你在根本性地改变整个模型和它的智能。

开放研究：不可信工作者池 [32:58]

Karpathy：AutoResearch 的并行化是有趣的部分。我更感兴趣的是：怎么有一个互联网上的不可信工作者池？

在 AutoResearch 中，你在找能把模型训练到很低 validation loss 的代码。如果任何人给你一个候选 commit，验证它是否正确很容易——你只需要跑一次训练。但产生那个 commit 需要大量搜索。可能有人试了 10000 个想法，但你只需要检查他们产出的那个是否 work。

我的设计看起来有点像区块链——不是 block 而是 commit，这些 commit 可以互相构建，包含改进代码的变更。Proof of work 就是做大量实验来找到有效的 commit。验证很便宜，搜索很贵。

这和 SETI@home、Folding@home 是同一类问题——产生很贵但验证很便宜。所以 AutoResearch@home 是个好的 fit。互联网上的 agent 群可以协作改进 LLM——甚至可能跑赢前沿实验室。前沿实验室有大量可信计算，但地球更大，有大量不可信计算。如果你建立了处理这个的系统，群体可能能想出更好的解决方案。

公司可以购买计算加入他们关心的 auto research swarm——也许你关心某种癌症，你不必只捐钱给机构，你可以购买计算加入那个项目的 auto research swarm。

就业市场与 Jevons 悖论 [37:57]

Karpathy：我对 AI 对就业市场的影响很好奇。我看了劳工统计局的数据——他们对每个职业有未来十年的增长预测。

我的框架是：当前开发的主要是数字 AI——像幽灵或精神实体，能在数字世界交互、操纵数字信息，但没有物理体现。物理的东西会慢一些，因为你在操纵原子。翻转比特和复制粘贴数字信息比加速物质快一百万倍。

所以数字空间会有巨量活动——巨量重写、沸腾的汤。数字空间会以光速前进，物理世界会滞后。

主持：工程岗位的需求在继续增加——这是暂时现象吗？

Karpathy：这是需求弹性。软件是稀缺的——我们没有更多软件需求只是因为太贵了。如果 barrier 降下来，你就有 Jevons 悖论——需求实际上上升。经典例子是 ATM 和银行柜员：ATM 让银行分行运营成本更低，所以有了更多分行，所以有了更多柜员。

我对软件工程持谨慎乐观态度。软件的需求会极其大，它只是变便宜了。代码现在是临时的、可以改变和修改的。你不被迫使用给你的任意工具。所以数字空间会有大量活动来重新布线一切。

长期来说——OpenAI、Anthropic 这些实验室雇了一千多研究员，这些研究员基本上是在积极地自动化自己。

· · ·

独立研究者 vs 前沿实验室 [44:37]

主持：你可以在前沿实验室做 auto research，为什么不去？

Karpathy：我去过一段时间，也重新加入过。有很多方式来切这个问题。我觉得人们在前沿实验室之外也能有很大影响——在生态系统层面的角色。

但也有一些问题。你和前沿实验室有巨大的经济激励绑定，而你自己承认 AI 会戏剧性地改变人类和社会。你在构建技术并从中获益——这是 OpenAI 最初试图解决的困境。

在前沿实验室内部，你不是完全自由的 agent。有些事你不能说，有些事组织希望你说。你感受到压力。我在前沿实验室之外感觉更与人类对齐——不受那些压力。

但反过来，如果你在外面，你的判断会开始漂移——你不了解即将到来的东西。所以理想的设置可能是进进出出——连接到实际发生的事情，但不完全被那些实体控制。

· · ·

开源与前沿的健康平衡 [49:00]

主持：开源离前沿有多近？这可持续吗？

Karpathy：闭源模型领先，但人们在监测开源落后几个月——从无到 18 个月，现在大概 6-8 个月。

类比操作系统：有 Windows 和 macOS 这些闭源大项目，也有 Linux。Linux 极其成功——跑在大多数计算机上。因为行业需要一个大家都觉得安全使用的公共开放平台。LLM 也一样。

大区别是资本支出。这让竞争更难。但对于绝大多数消费者用例，开源模型其实已经相当好了。再过几年，大量简单用例会被很好覆盖，甚至本地运行。

但总会有对前沿智能的需求——可能是诺贝尔奖级别的工作，或者"把 Linux 从 C 重写成 Rust"这种大项目。前沿闭源智能可能在那里交互，开源吃掉更基础的用例。

我觉得我们意外地处于一个还不错的位置。我对只有闭源智能有系统性风险的担忧——中心化在历史上有很差的记录。我希望有一个东西在能力边缘后面一点，作为整个行业都能访问的公共工作空间。

我几乎希望有更多前沿实验室。在机器学习中，ensemble 总是优于单个模型。我希望有 ensemble 的人在思考最难的问题、在房间里做决策。不要闭门两三个人——那不是好的未来。

数字 vs 物理：原子比比特难一百万倍 [38:32]

Karpathy：自动驾驶是第一个机器人应用。我看到的是大量资本支出和时间。机器人因为太难、太乱、需要大量资本投入，会滞后于数字空间。

但有趣的是数字和物理之间的接口。如果我们有更多 agent 代表人类行动、互相交流、参与 agent 经济，你会用完纯数字空间能做的事。某个时候你必须去问宇宙问题——跑实验看宇宙告诉你什么。

我们目前有大量数字工作的 overhang——人类集体没有足够的思考周期来处理所有已经数字化的信息。但我们会开始用完已经上传的东西。

所以轨迹是：首先数字空间大量 unhobbling → 然后物理和数字的接口（传感器看世界、执行器操纵世界）→ 然后物理世界本身。物理世界的 TAM 可能更大，但原子难一百万倍，所以会滞后。

我对信息市场感到惊讶——为什么没有一个流程让"从德黑兰某处拍张照片"只花 10 美元？不会是人在看，而是 agent 在猜赌博市场和股市。Agentic web 还很新，没有这种机制。

MicroGPT 与教育的重塑 [1:01:34]

Karpathy：MicroGPT 是我十几二十年来把 LLM 精简到本质的执念的最新成果。训练神经网络和 LLM 有大量代码，但所有代码的复杂性都来自效率——因为需要跑得快。如果你不需要快、只关心算法，那算法就是 200 行 Python。包括注释。

以前如果我做出 MicroGPT，我会想做个视频逐步讲解。但我意识到这不太增加价值了——因为它已经简单到 200 行，任何人都可以让 agent 用各种方式解释。我不再向人解释了，我向 agent 解释。如果你能向 agent 解释，agent 就能做路由器，用无限耐心、按人的能力水平、用他们的语言来讲。

教育以前是指南、讲座。但现在我更多是向 agent 解释东西，也许我在写 skill——skill 就是指导 agent 怎么教这个东西的方式。也许我可以为 MicroGPT 写一个 skill，描述我想象 agent 应该带你走过的进程。我只是稍微编排课程作为 skill。

所以教育会被相当大地重塑。不再是直接向人解释。如果我有个代码库，以前你有给人看的 HTML 文档。但你不应该再这样做了——你应该有给 agent 看的 Markdown 文档，因为如果 agent 懂了，它们就能解释所有不同部分。

MicroGPT——我试过让 agent 写它。我告诉它"试着把神经网络训练精简到最简单的东西"。它做不到。MicroGPT 是我执念的终点——200 行，我想了很久，这是解决方案，不能更简单了。这是我的价值贡献——那几个 bit。其他一切——之后的教育——不再是我的领域了。

Agent 能做的事，它们大概能做得比你好，或者很快就能。所以你应该战略性地选择你实际花时间在什么上面。
