核心实验

2025 年 9 月，OpenAI 推出 GPT-5-Codex 作为第一个为 agentic 编码优化的 GPT-5 版本。2025 年 12 月推出 5.2 版本，人们开始相信使用自主编码 agent 可以是可靠的——特别是模型能可靠遵循指令的时间跨度有了巨大飞跃。

作者想压力测试这个阈值。给 Codex 一个空仓库、完全访问权限和一个任务：从零构建一个设计工具。然后让它以 GPT-5.3-Codex 的"Extra High"推理模式运行。Codex 不间断运行了约 25 小时，使用了约 1300 万 token，生成了约 3 万行代码。

这是一个实验，不是生产部署。但它在长周期工作的关键方面表现良好：遵循 spec、保持专注、运行验证、在过程中修复失败。

· · ·

真正的转变是时间跨度

这不仅仅是"模型变聪明了"。实际变化是 agent 能保持连贯更长时间，端到端完成更大块的工作，并在不丢失线索的情况下从错误中恢复。

METR 关于时间跨度基准的工作为这一趋势提供了有用的框架：前沿 agent 能以约 50% 和 80% 可靠性完成的软件任务长度一直在快速攀升，大约 7 个月翻倍。

GPT-5.3-Codex 在两个实际方面推进了 agent 工作：

  • 更擅长多步执行（计划 → 实现 → 验证 → 修复）
  • 更容易在运行中途引导而不重置整个运行（航向修正不会擦除进度）

Cursor 团队写道 OpenAI 模型"在扩展自主工作方面好得多：遵循指令、保持专注、避免漂移、精确完整地实现事物。"

· · ·

为什么Codex能在长任务上保持连贯

长时间运行的工作不是关于一个巨大的 prompt，而是关于模型运行其中的 agent 循环：

1. 计划 2. 编辑代码 3. 运行工具（测试/构建/lint） 4. 观察结果 5. 修复失败 6. 更新文档/状态 7. 重复

这个循环之所以重要，是因为它给 agent 提供了：

  • 真实反馈（错误、diff、日志）
  • 外化状态（仓库、文件、文档、worktree、输出）
  • 随时间的可引导性（你可以基于结果进行航向修正）

这也是为什么 Codex 模型在 Codex 界面上比通用聊天窗口感觉更好：harness 提供结构化上下文（仓库元数据、文件树、diff、命令输出）并强制执行有纪律的"完成条件"例程。

· · ·

实验设置：持久项目记忆

最重要的技术是持久项目记忆（durable project memory）。作者将 spec、计划、约束和状态写在 Codex 可以反复查阅的 markdown 文件中。这防止了漂移并保持了"完成"的稳定定义。

文件栈如下：

Prompt.md（spec + 交付物）

冻结目标，防止 agent "构建令人印象深刻但错误的东西"。包含：

  • 目标 + 非目标
  • 硬约束（性能、确定性、UX、平台）
  • 交付物（完成时必须存在什么）
  • "完成条件"（检查 + 演示流程）

Plan.md（里程碑 + 验证）

将开放式工作转化为 agent 可以完成和验证的检查点序列。包含：

  • 足够小以在一个循环中完成的里程碑
  • 每个里程碑的验收标准 + 验证命令
  • 停止修复规则：如果验证失败，修复后再继续
  • 决策笔记以避免振荡

Implement.md（引用计划的执行指令）

运行手册——告诉 Codex 如何操作：遵循计划、保持 diff 范围、运行验证、更新文档。

Documentation.md（状态 + 决策）

共享记忆和审计日志。让人可以离开几小时后仍然理解发生了什么。包含：

  • 当前里程碑状态
  • 做出的决策（及原因）
  • 如何运行 + 演示
  • 已知问题/后续

· · ·

Agent构建了什么

结果不完美也不是生产就绪的，但它是真实且可测试的。标准不是"能编译"，而是"它遵循指令了吗，它实际工作吗？"

实现的高级功能：

  • 画布编辑（框架、组、形状、文本、图片/图标、按钮、图表）
  • 实时协作（在线状态、光标、选择、编辑跨标签同步）
  • 检查器控件（几何、样式、文本）
  • 图层管理（搜索、重命名、锁定/隐藏、重排序）
  • 参考线/对齐/吸附
  • 历史快照 + 恢复
  • 回放时间线 + 从先前点分支
  • 原型模式（热点 + 流程导航）
  • 评论（固定线程，解决/重新打开）
  • 导出（保存/导入/导出 + CLI 导出为 JSON 和 React + Tailwind）

· · ·

长周期Codex任务的要点

让这次运行成功的不是一个聪明的 prompt，而是以下组合：

1. 明确的目标和约束（spec 文件） 2. 带验收标准的检查点里程碑（plans.md） 3. agent 应如何操作的运行手册（implement.md） 4. 持续验证（测试/lint/typecheck/构建） 5. 实时状态/审计日志（documentation.md）使运行保持可检查

这是长周期编码工作的发展方向：更少的看护，更多带护栏的委托。
