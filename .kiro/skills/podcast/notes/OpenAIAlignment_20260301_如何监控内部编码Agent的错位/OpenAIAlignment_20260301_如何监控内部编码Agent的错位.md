## 背景与动机

AI 系统正在以更大的自主性在真实环境中大规模运行。随着能力提升，它们能承担越来越复杂、高影响的任务，并以类似人类协作者的方式与工具、系统和工作流交互。

OpenAI 使命的核心部分是帮助世界负责任地过渡到 AGI。这不仅意味着构建高能力系统，还意味着开发部署和管理这些系统所需的方法、基础设施和策略。

**监控内部部署的 agent** 是我们实现这一目标的关键方式之一，它让我们既能从真实使用中学习，也能识别和缓解新出现的风险。过去几个月，我们构建并完善了一套针对内部编码 agent 的监控系统，作为更广泛安全策略的一部分。本文描述该系统的工作原理、我们目前的发现，以及我们对这种方法未来演进的看法。

在内部使用高级编码 agent 让我们有机会理解它们在真实工作流中的行为，以及用户如何将这些 agent 应用于跨多种环境的复杂、工具密集型任务。OpenAI 内部的编码 agent 部署还带有独特的错位风险因素：它们能访问部分内部 OpenAI 系统，能检查其安全措施的文档和代码，甚至可能尝试修改这些安全措施，还能以可能影响其未来版本的方式采取行动。这些特性使内部部署成为创新监控基础设施的独特重要场景，我们认为类似的安全措施应该成为全行业内部编码 agent 部署的标准。

## 我们的方法及其工作原理

随着能力提升，我们认为监控 agentic 行为——包括模型的动作和内部推理——将成为越来越重要的安全工具。监控内部编码 agent 帮助我们理解错位行为发生的频率和具体表现。目标是标记那些在模型部署前难以发现的错位相关行为，因为这些行为往往只在真实的、工具密集的工作流和长时间会话中才会出现。同时，保护编码 agent 会话中的用户隐私和数据安全也至关重要，只能以严格限定范围的方式暴露问题行为。

为此，我们开发了一套**低延迟内部监控系统**，由 GPT-5.4 Thinking 以最大推理力度驱动，审查 agent 的交互并在发现可能与用户意图不一致、或可能违反内部安全/合规策略的行为时发出警报。监控器记录和分析 agent 的思维链和动作，自动对可疑或有问题的行为发出警报，以便我们快速分类、缓解后果并改进其他安全措施。这个反馈循环让我们能快速检测和解决潜在安全问题、改进模型对齐，是我们长期 agent 安全策略的核心组件。

在最新形态中，我们的监控系统在交互完成后 **30 分钟内**完成审查，对交互进行分类并分配严重程度等级。随着延迟向近实时审查降低，安全收益将显著增加。最终，监控器可能能在编码 agent 采取行动**之前**评估其动作——在现有安全监控之外提供又一层纵深防御。

初步结果表现强劲：监控系统持续优于员工上报——标记了员工通过内部渠道独立报告的每一个交互。监控器还发现了许多可能被内部用户忽略的额外行为。

通过这项工作，我们发现模型在追求用户指定目标时可能**过于急切地绕过限制**，尤其是当用户请求无意中鼓励了这种行为时。不过，到目前为止我们没有看到超出原始任务的动机证据（例如自我保护或 scheming）。极小比例的流量（<0.1%）——主要来自定制或本地设置——目前在我们的监控覆盖范围之外，我们正在努力弥补这一缺口。

## 监控内容

监控系统在所有标准内部编码 agent 部署上私密运行，查看完整的对话历史，包括所有思维链、所有用户/开发者/助手消息，以及工具调用和输出。系统识别与用户意图不一致或其他可疑的行为（如试图绕过限制），一旦检测到潜在异常，就会提交给人类审查和处理。这限制了人类审查的工作量，同时让我们能识别和响应影响模型对齐或行为的潜在问题。

### 类别概述

每个类别包含：(1) 简短定义，(2) 我们在内部部署中观察到的情况，以及定性频率标签。这些标签反映通过此监控方法观察到的行为的相对频率和严重程度。"常见"指的是不到总流量的 1%。

在我们运营该系统的五个月中，我们监控了**数千万条**内部 agentic 编码轨迹。**零条**真实对话触发了最高严重级别——该级别旨在捕获罕见的高风险错位（如连贯的 scheming）——我们目前只在具有挑战性的合成评估中观察到这种情况。大约 **1,000 条**对话触发了中等严重程度的警报——其中许多来自刻意的内部红队测试——并被提交给人类审查，自动通知我们的安全监督和安全事件响应调查团队进行进一步调查。

## 局限性

我们发现这种内部错位监控方法在覆盖能力和资源效率方面非常有效，但它有局限性：首先也是最重要的，这种方法关键依赖于**可监控性（monitorability）**，我们正在投入努力来保持这一特性。某些不当行为可能比其他行为更容易从模型推理和工具轨迹中检测到，未来的模型可能展现出更难识别的行为。

虽然系统到目前为止匹配了我们所知的每一次员工上报——这是一个积极信号，表明它能可靠地捕获明显的、高显著性的问题——但这本身并不排除更微妙的错位，我们仍然无法在开放式真实流量上自信地量化假阴性率（需要专门的控制评估和红队测试）。这就是为什么我们将监控视为纵深防御栈中的一层——投资于可监控的推理轨迹，并将监控与互补的评估和预防性控制配对。

## 迈向基于监控的安全论证

在我们继续提高可靠性的同时，当前的异步监控基础设施已经提供了一种实用方式来观察和学习模型在真实内部部署中的行为。我们将此视为迈向前沿 AI 系统更广泛**安全论证（safety case）**的早期步骤——将监控、评估和控制结合起来，随着能力增长管理风险。

通往这种基础设施的路线图包括：

- **控制评估（Control evaluations）**：让我们能估计监控器在对抗性构造分布上的召回率，以及我们根据监控预测采取行动防止伤害的能力——包括评估监控器是否可能与 agent 串通。作为第一步，我们开发了一个评估场景：agent 试图偷偷破坏提交到 OpenAI 代码库的 PR（详见 Guan et al., 2025）。在这个任务上，我们最新的监控系统取得了完美表现，尽管这个任务在很多方面对监控器来说不切实际地简单，我们正在努力理解当前系统的局限性。

- **监控器和人类审查者的可接受可靠性和延迟标准**，以及对底层监控系统隐私和安全控制的持续增强。

- **将监控扩展到同步阻断**：让系统能在模型动作执行前评估并阻止它们，而不仅仅是在事后不久发出警报。

## 前路

在当前限制范围内，该系统已经具有实际价值：如上所述，它发现了可能被忽略的额外案例，我们利用其发现做出了具体改进（包括更新相关安全措施和系统消息）。同样重要的是，其低延迟警报让我们能在问题发生后不久进行调查和遏制，限制潜在的下游影响。

尽管监控器目前以异步方式运行，我们预期它能显著降低那些在较长时间内展开的威胁模型的风险（例如数据投毒或研究破坏），因为捕获早期行动可以防止更大的下游伤害。

我们的目标是在内部建立稳健的监控实践，通过真实世界经验加强它们，并最终帮助使类似的安全措施成为全行业标准。展望未来，我们计划探索更同步的监控栈——能在执行前评估并可能阻止最高风险的行动——尤其是在单个步骤可能造成不可逆伤害的场景中，并预期将继续使用我们最强大的模型来完成这项任务。
